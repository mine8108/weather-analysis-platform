# 气象分析工作台六模块改版执行方案

更新日期为 2026 年 10 月 26 日，版本为执行状态版。目标是在保留天空配色、天气卡片和现有业务能力的基础上，尽量忠实复现已选图片的视觉效果，建立导航清晰、分析区域突出、结果可核查的专业气象分析工作台。范围覆盖数据导入、可视化分析、数值预报、AI 读图解析、报告导出、报文解码。

本方案以本地提交 `6531f89`、应用版本 `2.3.9` 为编制基线。原阶段完成了六模块本地实现、视觉对照和 556 项回归。随后扩展到 41 城地标和 2.4.0，发布进度以执行记录为准；3 项独立测试后端用例与真实设备验收继续单独标注，不用本地通过替代。工作分支为 `codex/weather-workbench`。

当前状态以 [执行与验收记录](design/workbench-20261026/execution-audit.md) 和根目录 [视觉验收](../design-qa.md) 为准。后续经用户单独授权建立了独立 Supabase 测试项目，具体变更、TLS 连接阻碍和仍待完成的设备验收已记录。用户随后授权留档、将 41 城地标接入运行时，并将最新设计合入 main 更新现有线上网站；发布证据见后续记录。

最高优先级是已选展开天气墙中的天空质感、云层体积、前后景关系与文字层级。用户标注位置为原图宽度的 81.3%、高度的 41.1%，位于右下方成都卡片的云雾场景区域。静态效果先达到可对照验收的质量，再加入短动效和真实交互。

## 一 目标与范围

### 已确定的设计规则

- 采用统一顶部六模块导航，当前模块具有明确选中态；天气区域始终位于导航下方。
- 保留浅蓝、淡紫、暖白天空背景及蓝灰天气卡片；图表和文档使用近白底。
- 六模块共用顶部紧凑城市天气带，点击“展开天气墙”后原位展开完整卡片。展开与收起不切换模块。
- 移除旧效果图中的右侧天气栏；分析主区获得完整宽度。页面自身的图层设置、AI 原图和报告选项可以按任务保留分栏。
- 点击城市先确认预报时段，确认后进入数值预报模块；已经在数值预报页时更新对应城市。取消保留原页面和结果。
- 城市地标按 2026-10-28 最新决定仅在鼠标悬停天气图像区域时显现，平时完全隐藏；进页、触屏点击和键盘聚焦都保留天气画面。
- 天气卡片平时静止。只有实际进入页面时短暂播放，以及鼠标悬停在天气图标区域时播放；移开即停止。整张卡片悬停、数据刷新、控件重绘均不额外触发动效。
- 紧凑天气带默认全站可见；尊重已有用户主动隐藏偏好，并保留“显示城市天气”入口。展开状态跨模块保留，确认进入预报后主动收起以展示图表。
- AI 生成前删除“本次将得到什么”整个板块。右侧直接展示解读关注点、额度、生成按钮和简洁的完整解读结构。
- AI 生成后依次展示核心结论、原图依据、不确定性、完整六段正文和导出操作。
- 效果图中的示例数据、文字和装饰不构成计算规则。真实统计、阈值、单位和字段以经过核对的数据契约为准，生成图中的错误刻度和装饰数字不进入产品。

## 三 技术路线与基础架构

### 沿用当前技术栈

继续使用 Python、Streamlit 1.66.1、Plotly 6.8.0、pandas 3.0.3 和 python-docx，复用现有认证、数据访问及配额模块。版本以当前 requirements 和执行环境为依据，不为本次视觉改版升级整套依赖。本地已核实 `st.navigation` 支持 `position="top"`；官方说明见 [顶部导航接口](https://docs.streamlit.io/develop/api-reference/navigation/st.navigation)。

首选使用原生顶部导航配合六个页面渲染入口。先以两页样板验证固定导航、跨页状态、主题和窄窗口行为，再推广。固定效果与品牌栏排列必须浏览器实测，接口存在不等于视觉验收通过。

若原生导航在必要布局或状态兼容上失败，保留现有单入口路由，以原生分段控件实现顶部选项。该降级需要记录偏差，仍须通过导航可达、选中态和滚动可用性验收；不能以更换框架作为默认补救。

### 提取顺序

1. 将 app.py 中六个条件分支提取为薄页面函数，先保持业务调用与状态键不变。
2. 将公共品牌栏、页面标题、全站天气区域和状态提示集中到公共 UI 层。
3. 接入导航适配层，统一程序内跳转和返回行为，避免新旧导航同时写状态。
4. 将 UI 偏好与业务数据分开；数据、预报、AI 结果使用独立于控件生命周期的状态键。
5. 按模块替换布局，逐阶段进行回归；不同时重写计算函数。

下表保留原定职责划分；已经实施的具体文件及替代路径以当前代码和执行记录为准：

| modules/ui/components.py | 页面标题、状态条、指标组、主次操作组件 |

### 天气交互组件

天气图形与精确悬停事件采用局部 HTML、CSS、JavaScript 组件，Python 仍负责取数、身份校验、额度和页面路由。首选验证现有版本提供的 `st.components.v2.component`，通过受控数据和事件与应用通信。组件样式隔离只解决样式冲突，外部城市名仍需以纯文本填入。接口依据见 [组件注册](https://docs.streamlit.io/develop/api-reference/custom-components/st.components.v2.component) 和 [组件挂载](https://docs.streamlit.io/develop/api-reference/custom-components/st.components.v2.types.componentrenderer)。

P0 先验证稳定 key、局部事件、样式变量、图片资源加载、主题、销毁清理和 Streamlit 重绘行为。素材通过项目支持的组件资源或受控静态资源路径交付，不能将本机文件路径写进浏览器地址。不得通过父页面 DOM 探测模拟点击或监听内部 React 节点来完成路由。

当前本地 v2 组件已通过点击回传、展开收起、路由联动、进页及悬停验收。若以后在部署环境存在实证兼容问题，再验证 v1 双向组件作为后备；需额外处理 iframe 高度和主题。不能静默退回无交互截图，或因样板失败直接重写整站。

### 状态与数据约束

- 新增状态键登记到 modules/app_state.py；切页、返回、主题切换和面板收起均不清除业务结果。
- 控件隐藏或跨页消失时，其业务值仍可恢复；不依赖控件键永久存活。
- 全局时间筛选与模块专用筛选明确区分，避免预报时效反向修改观测分析范围。
- 天气关注列表与当前预报结果仍使用独立状态；仅由确认动作显式建立一次城市与时段联动。
- 天气状态从当前导入模块作用域迁入全站 UI 状态；重置导入或 AI 模块不删除城市。登出清理用户关联的会话快照，持久化偏好继续按现有用户隔离。
- 区分待查看城市、请求中的城市和已成功加载城市；所有标题、图表、建议、当前天气与导出必须读取同一个成功结果上下文。
- 城市身份使用稳定坐标标识配合显示名称，禁止只靠城市名绑定数据；重复名称、同城不同坐标和删除重加均须验证。
- 报告继续按输入指纹失效重建，防止展示新数据却下载旧报告。
- 冻结原图顺序、哈希和生成时输入，后续上传变更不能把旧结果绑定到新图。
- 认证与配额代码不因 UI 改版被绕过。不得为方便截图修改生产登录门禁。

### 组件与业务之间的最小契约

下表是计划中的结构边界，最终字段名在 P0 固定，避免页面各自维护城市和预报副本。

| 对象 | 必需内容 | 约束 |
| --- | --- | --- |
| 天气卡片数据 | 城市 id、名称、请求坐标、天气码、描述、场景、昼夜、数值和单位、有效时间、获取时间、时区、缓存状态 | 展示文本与场景独立；未知和缺失有明确值 |
| 全站天气 UI 状态 | 显示偏好、展开状态、当前页面进入标识、动态开关 | 不混入预报筛选；展开态属于会话状态，不必写入云端 |
| 预报查看意图 | 请求 id、城市 id、坐标快照、天数、模式、来源模块与筛选 | 确认前不触发 GFS；消费后不重复提交 |
| 成功预报上下文 | 请求 id、城市、坐标、模式、实际覆盖期、数据指纹、数据、单位、获取时间和来源 | 所有指标、当前天气、辅助图与导出共同读取 |
| 天气组件事件 | 选择城市、展开或收起、显式刷新、管理城市 | 事件名白名单；Python 按城市 id 重新校验城市和坐标 |
| 动画内部状态 | 进入播放、图标悬停、静态、暂停与销毁 | 留在浏览器；悬停不发送 Python 事件，不触发重绘和取数 |

组件使用原生可聚焦按钮承载城市查看操作，天气图形为装饰层；避免嵌套按钮。管理和删除入口与查看操作分离。新字段通过现有状态注册和序列化边界，不能把账号、密钥或完整后台对象交给天气前端。

### 组件与窄窗口规则

大桌面保持三列完整天气卡片和全宽图表；中等宽度改两列，小屏一列。紧凑态在桌面显示约四张卡片，其余用可操作的横向列表查看；展开态保留全部关注城市。现有最多六城的上限不扩大，不自动填入示例城市。少量城市只占实际需要的行数，空状态提供添加与定位入口。

首轮断点以 1200 和 768 px 为起点，通过 1487 × 1058 主基准及 390、463、768、1024、1440、1920 px 验证后调整。手机紧凑卡片允许横向滑动，保留可见的下一张边缘和切换按钮，页面本身不得横向溢出。工具栏换行，天气墙按自然文档流展开，不覆盖模块内容。

品牌和导航可在空间充足时固定，完整天气墙不固定悬浮。小屏优先保留模块导航；AI 的内容顺序为原图入口、核心结论、依据、不确定性、完整正文。AI 原图、报告选项等任务内分栏在小屏顺序堆叠。

浅色与暗色均使用真实 token。正文一般为 14 至 16 px，模块标题约 18 至 20 px，页面标题约 26 至 28 px。色彩标识同时配合文字、线型或图标，关键状态不能仅靠颜色区分。

## 五 天气墙视觉与动效复现

### 静态视觉规格

首轮按主图同尺寸对照，再调整到响应式布局。以下数值为起始实现规格，最终以同视口截图比较为准。

| 元素 | 起始规格 | 复现重点 |
| --- | --- | --- |
| 页面边距 | 桌面约 32 至 40 px，小屏 16 px | 与导航、天气墙和图表边缘对齐 |
| 品牌栏及导航 | 各约 52 至 58 px | 云标、深蓝标题、克制分隔与蓝色选中线 |
| 完整卡片 | 三等宽列，间距 16 至 20 px，高约 170 至 184 px | 保留横向天空画面，避免做成普通统计方块 |
| 紧凑卡片 | 高约 92 至 104 px，图标在右侧 | 城市、温度、天气和今日高低温清楚可读 |
| 卡片文字 | 城市约 22 至 26 px，温度约 48 至 56 px，辅助信息 14 至 16 px | 左侧信息区稳定，不随云层移动 |
| 天空画面 | 右侧主要视觉，背景延伸覆盖整卡 | 云团有体积、边缘有透光、雨幕有前后层次 |
| 云雾远景 | 低饱和远景与半透明近雾 | 重点复现用户标注的成都卡片质感 |
| 选中状态 | 细蓝描边与“正在分析”标记 | 仅代表已成功加载的预报城市 |
| 操作入口 | 一致线性图标、明确可点击区域 | “添加”“刷新”“收起”各自独立，不复用错误图标 |

采用中文可读性优先的字体栈，并核查 Windows、云端和浏览器字体回退。温度可使用较圆润数字字体，正文保持清晰。天气图像与文字重叠时，通过素材构图、文字区遮罩和对比度控制解决，不能把背景整体压黑而丢失层次。

图中的城市远景属于氛围插画，不能标注为城市实时摄像或实景照片。真实地点和经纬度来自城市数据，不能照抄示意图。深色界面不应把白天晴天自动改为夜景，天气昼夜由 `is_day` 决定。

### 素材生产与交付

现有卡片主要由 CSS 云形和基础渐变构成，已选图的云层与远景细节需要专门的图像素材。先制作晴、多云、雨三种完整样板，再补齐阴、雾、雪、雷雨和晴夜。每个场景都交付静态封面和必要的独立前景层。

| 素材 | 处理方式 | 交付要求 |
| --- | --- | --- |
| 天空和远景 | 按参考图方向生成无文字场景底图 | 无温度、城市名、按钮或假数据；预留左侧文字安全区 |
| 近云与远云 | 分别生成透明素材，保留柔软边缘 | 至少两层可独立移动，静止时构图与封面一致 |
| 太阳、雨丝、雪片、雾层 | 同一视觉风格的独立图像素材 | 不用圆形拼接云朵替代参考质感；粒子数量受控 |
| 静态封面 | 与动态层的默认状态一致 | 禁用动态、触屏、截图和低性能环境仍保持完整效果 |
| 通用图标 | 复用最接近参考的现有图标库 | 不用彩色 emoji 混入导航和操作按钮 |

素材先以约 2 倍显示分辨率制作，保留高质量原稿，运行时优先使用合适尺寸的 WebP 或带透明通道的图像。各素材记录生成来源、用途、尺寸与压缩版本。网页加载运行时素材，不加载九张整页参考图；归档参考图共约 13.6 MB，不能作为页面资源整体下发。

优先采用分层图片配合 transform 和 opacity 做动画。仅当样板明确证明图像分层无法达到视觉目标时再评估视频或更重的渲染方案；无条件引入实时 3D 会增加性能和维护成本，不作为首选。

### 精确动效规则

用户已选择静态为主，进页和天气图标悬停时出现动态。天气图标指云、太阳、雨雪等图形所在的区域，通常位于卡片右侧；城市文字、温度、整张卡片和右下跳转箭头不作为悬停播放触发区。

| 触发或状态 | 行为 | 初始参数 |
| --- | --- | --- |
| 实际进入页面 | 可见卡片播放一次轻量场景动画，结束恢复静态封面 | 场景约 1.5 至 2.5 秒，总体不超过约 3 秒 |
| 首次入场排布 | 轻微淡入，可按卡片错开 | 约 200 至 300 ms，错开约 30 至 50 ms，无弹跳 |
| 天气图标悬停 | 仅当前卡片的天气层播放；停留期间允许柔和循环 | 云缓移，雨雪短距离落下，光照小幅变化 |
| 鼠标离开图标 | 停止播放并平滑回到静态构图 | 约 150 至 250 ms 内完成，无突然闪白 |
| 卡片文字和箭头悬停 | 仅保持普通颜色、边框或焦点反馈 | 不启动场景动画，不移动整张卡片 |
| 展开与收起 | 可以有一次短布局过渡，不重播天气入场动画 | 约 180 至 240 ms，不滚动挤压当前输入焦点 |
| 筛选、刷新、主题切换、Streamlit 重绘 | 更新数据与外观，维持静态或现有用户悬停状态 | 不作为重新进页，不重置所有动画 |
| 触屏设备 | 只保留短暂进页动画，之后静止；点卡片仍进入预报确认 | 不要求 hover，不把长按变为必要操作 |
| 页面不可见、卡片离屏、弹窗打开 | 停止天气动画 | 不在后台持续运算 |
| 系统减少动态或用户关闭动态 | 使用完整静态封面 | 保留所有信息和功能 |

云层初始位移控制在数个像素量级；雨雪粒子只覆盖图形区域，文字数值完全静止。雷雨采用云层和雨幕表达，避免强闪光。动效是天气类别的装饰表达，不按风速或雨量数值模拟物理运动。

前端用稳定的页面进入标识区分真正切页与重复渲染；每个标识的入场动画最多消费一次。销毁时移除监听器、定时器和动画，关闭弹窗或回到标签页后不自动补播。减少动态依据 [prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)，清理生命周期依据 [组件清理函数](https://docs.streamlit.io/develop/api-reference/custom-components/component-v2-lib-cleanupfunction)。

### 全站行为和数据呈现

城市列表、排序、显示偏好和展开状态在六模块共享。现有搜索、经纬度输入、同名城市选择、定位、刷新、删除与城市持久化均保留。删除移入明确的管理操作，避免与整卡点击预报冲突。暂时隐藏天气后仍可通过顶部入口恢复。

天气卡片呈现城市、坐标、当前温度、真实天气描述、今日最高最低、湿度和风速；AQI 可置于完整态的辅助信息或详情中，不能因参考图未展示就删除已有能力。来源、有效时间和缓存状态可通过天气区域说明与卡片详情查看。

取数按城市集合批量进行。初次加载、显式刷新和城市集合变化可以触发取数；切页、展开、悬停、关闭确认框使用现有快照。沿用缓存和出站配额约束，缓存有效期不等于自动刷新计时器，不新增无限轮询。手动刷新只使相关城市查询失效，避免清空所有用户的天气缓存。

当前代码与官方字段规则核对后，以下修正与天气墙一起交付，并通过独立行为测试验证。

| 位置或问题 | 处理 |
| --- | --- |
| weather_wall.py 当前请求未指定风速单位，返回值直接显示为 m/s | 明确请求 m/s 并验证响应单位；缓存增加版本或失效处理，不能让旧 km/h 数值继续按新单位显示 |
| current 数据的来源文案 | 使用“当前天气”等准确措辞；该端点是模式数据，不标为站点实测 |
| scene 名称直接用作天气描述 | 场景素材与描述分开；阴天不强行写为多云，中雨不写成小雨；未知代码显示未知 |
| 回退数据丢失来源和时间 | 保存有效时间、取数时间、时区与缓存标记，失败时明确展示旧数据或无数据 |
| 同名城市数据只以名称关联 | 内部按稳定城市标识和坐标绑定，名称仅作显示 |

Open-Meteo 官方文档列出默认风速单位为 km/h、current 的模式数据属性及天气代码含义，见 [天气接口字段说明](https://open-meteo.com/en/docs)。这些修正限定于已核实的数据展示契约，其他分析算法保持现有范围。

## 六 城市联动与图表信息优化

### 城市至预报的完整流程

1. 用户点击城市卡片或其查看箭头，仅创建待查看意图并打开确认框，不请求 GFS。
2. 确认框显示城市、坐标、当前天气缩略图，以及 3、7、16 天快捷选择，默认 7 天。预报主页面继续提供现有 1 至 16 天自定义选择。
3. 时段说明包含实际起止日期和时区。快捷天数按当前接口的日历日窗口计算，包含今天，不宣称固定的未来 72、168 或 384 小时。
4. 取消、关闭按钮和 Esc 均清除待查看意图，恢复点击卡片的焦点；原模块和已加载结果不变。
5. 确认后记录来源页面与筛选快照，进入数值预报页并收起完整天气墙，提交一次与请求标识绑定的加载。已经在预报页时保持页面，执行同一结果更新流程。
6. 成功后一次性更新城市、坐标、模式、时段、数据、指标和导出上下文，再将天气卡片标为“正在分析”。迟到结果不得覆盖后发请求。
7. 失败时保留明确标有原城市的旧结果，提示新城市获取失败，提供重试和返回；禁止新标题搭配旧曲线。当前天气请求、空气质量和建议也必须绑定结果坐标。
8. “返回原分析”恢复来源模块及筛选；预报模块内部保留至少上一份结果的会话快照，历史容量有界，不建立无限增长的历史系统。

确认事件携带请求 id，完成后消费，普通重绘不能再次提交。点击过程与查询是否命中缓存分开记录。点击天气卡片不自动调用 AI，也不把天气城市写入用户上传观测数据的站点筛选。

### 图表主次关系

页面顺序采用城市和模式信息、时段控制、关键指标、温度及降水主图、风场与空气质量、详细分析和预报验证。主图近白底；图例位于绘图区外，标题、单位和来源不压在曲线上。

温度与体感温度位于上层，降水位于下层，共用时间轴。温度为实线，体感为虚线，降水为蓝色柱；保留数据间断，不用视觉平滑掩盖突变或缺测。上下图缩放与悬停需要同步验证，不能仅在图片中对齐。

| 展示项目 | 实施规则 |
| --- | --- |
| 关键指标 | 最高、最低和累计降水基于明确的所选时段；同时显示极值发生时间，缺数据时给出覆盖说明 |
| 悬停信息 | 城市、时间和时区、变量名、单位、数据来源；累计量显示窗口起止与有效小时数 |
| 降水柱 | 默认 12 小时累计，核查原始逐时量的有效区间；统一窗口边界与标记，不能把累计量写成 mm/h |
| 缺失与部分窗口 | 全缺失保留为空；不完整 12 小时窗口默认留空或明确标为部分累计，不能伪装为完整窗口 |
| 日期与时间 | 短时段可展示小时，长时段按日疏排；标明北京时间 UTC+8，跨时区城市另显示其当地时间说明 |
| 元数据 | 区分资料有效时间、获取时间和模式起报时次；上游未提供起报时次就不填造 |
| 图层 | 体感、极值、阈值、日变化范围可控制；默认只保留完成主任务所需的信息 |
| 日最高最低包络 | 若保留，明确标为日变化范围，不能呈现为预测置信区间 |
| 极值与阈值 | 只标关键点；业务阈值来自现有配置，不把示例 19°C 当作阈值 |
| 风与空气质量 | 风注明 GFS，空气质量注明 CAMS；AQI 需数值和等级，不能只留一排彩点；超出空气质量覆盖期留空 |
| 导出 | 图像、HTML、CSV 与当前结果和视图范围一致；记录来源、单位和时间信息 |

删除以天气代码映射得到的“降水概率”曲线与幕布；只有上游实际提供并确认可用的概率字段才显示概率，缺失不能填成 0%。删除未经校准的“0至3天高、4至7天中、8天后低”可信度徽标和“精度增强”标题。需要解释远期时效时使用普通文字说明，不给出虚构的定量置信度。

日历日预报窗口、逐时降水有效区间和单位规则见 [Open-Meteo 字段定义](https://open-meteo.com/en/docs)。改动聚焦标注、有效区间、数据缺失与展示聚合，不扩大到新的预报算法。

## 七 AI 解读专项

### 生成前

最终版直接显示原图预览和解读关注点；“本次将得到什么”不再出现。额度概要显示真实服务端返回值，详细估算和计费说明折叠。未上传、图片不合格、额度不可用、生成中、失败与待结算状态具有明确文案和按钮状态。

当前单图业务上限为 1.5 × 1024 × 1024 字节、最多5张、合计7.5 MiB。现有文案使用MB，实施时要统一单位说明。Streamlit 的 `max_upload_size` 为整数MB，不能未经验证直接填1.5。优先验证每控件2MB传输上限配合严格1.5MiB业务校验，并在同一区域明确两者含义；若要完全隐藏框架文案，必须使用局部适配且保留上传限制的可访问说明。不得把业务上限提高到2MB来迎合控件。接口依据见 [文件上传控件](https://docs.streamlit.io/develop/api-reference/widgets/st.file_uploader)。

### 生成后结果模型

当前 build_chart_prompt 固定要求六段正文，parse_sections 仅切分中文方括号标题，无法直接支持可靠的逐结论依据关联。先定义版本化结果格式，再接入同一次模型请求。

| 字段 | 含义与校验 |
| --- | --- |
| schema_version | 结果格式版本 |
| source_images | 图号、文件名、哈希、尺寸；与本次提交快照绑定 |
| findings | 结论id、正文、图上可见或条件性解释、依据id、相关局限id |
| evidence | 依据id、图号、文字位置、可见特征；禁止引用不存在的图 |
| limitations | 具体缺失信息、影响的结论、可补充信息 |
| sections | 保留当前六段正文，兼容旧展示及导出 |
| raw_response | 保留模型原始响应供故障诊断与兼容，不向用户暴露敏感内部信息 |

现有六段标题保留为图像信息、图面要素识别、主要分布特征、关键数值与极值、趋势与演变、风险提示与结论。效果图里的缩略文字只用于界面导航，不擅自改写报告结构。

结论、依据和局限在一次响应中产生，避免额外调用模型生成摘要。先验证当前供应商的响应格式能力，不能预设支持严格JSON模式。缺字段或格式无效时保留原始正文并说明“结构化展示不可用”；不自动重试、不自动再次收费、不把解析失败伪装成成功。旧六段文本仍可阅读和下载，但不推造旧结果的证据关联。

模型生成的“图上可见”分类本身不代表人工已核验。没有依据的判断显示“依据未提供”；不能为了让界面完整而生成空泛证据。

### 证据定位分两级交付

一级为基础范围：图号、文字位置、可见特征、选择对应图片并查看原图。引用必须绑定生成时的原图。该级可先完整交付。

二级为条件范围：A/B框选、坐标定位和点击高亮。需验证模型确实提供有效坐标，完成原图到缩放预览的映射，并通过人工位置核对。只有越界校验通过仍不足以证明框选正确。无法可靠定位时隐藏框选，保留一级定位。

辅助标记独立叠加，可关闭，原图字节不被改写。默认Word导出保留原图；若以后导出标注图，需清楚注明为辅助标记。不得复制效果图中的框选当作实际模型输出。

### 用量与结果一致性

点击生成才允许发出一次请求；切页、收起原图、下载、主题切换和修改关注点均不自动调用。重新生成明确计入用量。解析或页面渲染失败不免除已经发生的调用结算。

保持现有预留、调用、用量归一、结算和释放流程；同一 call_id 不重复记账。成功结果按供应商实际返回用量处理，不能把 completion 内含的 reasoning 再次相加。旧成功结果在重生成失败后保留，但需标明对应旧输入，不能冒充新结果。

结构化结果渲染要转义文件名、模型正文与可见特征等外部内容，避免新增HTML注入路径。无业务必要不增加图片落盘或长期存储。

## 八 报告与解码增强边界

报告首轮交付为内容预览，展示实际章节、表格、数据范围和版本。预览与Word共用同一数据模型，避免另写一套统计。普通分析报告继续不含图片；AI读图Word报告继续按既有能力包含原图，两类报告不要混淆。

效果图的A4页面比例只作视觉参考。Word精准分页预览依赖额外转换与字体环境，不纳入首轮完成标准。生成按钮与下载按钮分别对应未生成和已生成状态，不能在尚无文件时展示一个假下载动作。

报文的字段来源采用解析器实际识别的 token 或位置索引。若当前解析器未保留来源，只做可验证的小范围提取扩展；无法对应的字段显示“来源定位不可用”，不靠字符串猜测。复制结果是新交互，须测试实际剪贴板行为，失败时保留可选取文本。

## 九 实施阶段和退出条件

依赖顺序为 P0 → P1 → P2 → P2B → P3/P4 → P5。每个阶段都提供可查看的阶段结果。先把天气墙做到可接受的视觉质量，再大面积套用六模块，避免后期重复返工。不同模块可在公共组件稳定后分别开展，具体执行方式由实施安排决定。

每阶段形成独立可回退提交。开始阶段前先验证上阶段状态，不在同一大提交中同时迁移导航、改动AI协议与调整报告生成。工期在P0样板验证后估算，以阶段通过为准，不把图片生成时间当作实现工期。

### 视觉与动态的专项验收

主视觉验收使用 1487 × 1058、相同六城示例和静态状态；另以 1486 × 1059 验收紧凑态。固定数据只存在于隔离样板与测试中，生产页面不得混入示例。对照时并排查看原图与实现截图，按布局、云层质感、文字、颜色、间距、裁切和选中态逐项记录差异。

可确定的几何值以像素测量，首轮目标是主要锚点误差约 4 px 以内、卡片尺寸误差约 3% 以内；字形栅格与生成图的不规则网格单独判断。这些是验收目标，不能据此宣称尚未实现的“百分之百还原”。用户特别标注的云雾远景必须单列对照，不能用简单图标通过该项。

短录屏至少覆盖静置 10 秒、进入页面、悬停图标、移到文字、移出、开关弹窗和减少动态。静置过程中没有场景动画；悬停无后台天气请求；重绘后无重复进场。触屏与键盘的城市选择、确认和返回可独立完成。

### 性能目标

以实测结果记录目标设备、浏览器、视口和网络条件。首轮以同时可见六张卡片时交互流畅为目标，动画期间争取稳定接近 60 fps，不把目标当作完成结果。静置时无持续动画循环、无新增定时取数；离屏与后台暂停。

初始天气素材传输目标不超过约 2 MB，优先复用、缓存和按需加载；超标先优化分辨率、压缩与透明层数量。快速进出图标和连续切页不堆积监听器或计时器。性能不足时减少动态层和粒子，保留高质量静态封面，不牺牲文字与图表可用性。

AI内容准确性与布局验收分开。离线固定响应只能验证展示和逻辑；后续若获准付费线上验证，使用一次小预算、无自动重试的受控样例，并核对应用记账。没有供应商账单证据时，不宣称供应商账单已核实。

## 十一 环境与回退

本地项目当前缺少 .streamlit/secrets.toml，不能据此判定正式登录和云数据联调已完成。离线UI和错误状态可先通过独立测试入口及依赖替身验证；该入口不可混入生产导航或提供认证绕过。

完整联调需配置受控测试后端或由用户提供可用的测试环境。不得将生产服务端密钥嵌入页面、参考图、文档、浏览器脚本或仓库。原图、账号和真实数据进入外部服务的范围保持现有授权边界。

回退按阶段提交恢复代码；AI响应同时保留原始正文，使结构化渲染出错时仍可阅读。公共导航回退后应明确保留哪些会话数据，部署重启导致的会话丢失需在发布说明中说明。默认不进行数据库迁移，避免UI回退与数据库状态互相牵制。

新版天气渲染和城市确认联动保留独立回退入口，旧城市持久化格式继续可读。新增预报上下文使用可重建的会话结构；数据展示单位修正不能随视觉回退恢复成错误单位。上线前验证静态资源路径、缓存版本和深色主题。

原方案阶段未授权部署。用户后续明确授权将最新设计与 41 城地标合入 main，并更新现有线上 Streamlit 网站进行测试。该发布范围不需要生产数据库迁移，也不包含付费 AI 调用。发布前保留源代码、工作目录及原线上基线，记录测试、截图、实际提交与回退方式。

## 十二 首批执行任务与最终交付

启动实施后首先完成以下可核查小批次：

1. 确认当前分支、提交、工作区与线上版本；保护既有未提交改动。
2. 核对本次已归档的九张参考图及哈希，完成现有功能与状态保留清单。
3. 拆解主图卡片素材，制作晴、多云、雨三个静态样板及进页、图标悬停、移开停止的短动效。
4. 用当前 Streamlit 版本验证一个双向天气卡片与两页导航；确认重绘不会重播，城市点击能够传回安全事件。
5. 展示主基准尺寸截图、窄窗口截图和动效录屏，按视觉差异继续修正；通过后再推广其余场景与六模块公共布局。

首批完成只代表视觉与交互技术路径成立。后续完整交付包括六模块可运行页面、天气素材源与运行版本、统一导航、GFS 联动、图表优化、AI 与报告兼容、相关测试结果、视觉差异记录、动效录屏、性能记录、用户手册和回退说明。

完整验收以实际运行页面为准。静态截图通过、动态通过、业务回归通过、用户接受和正式上线分别记录；只有对应证据齐备才标记完成。
