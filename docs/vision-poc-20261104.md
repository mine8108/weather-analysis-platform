# 气象工作台 AI 读图小规模验证

编制日期为 2026-11-04。目标是比较 OpenAI 与现有视觉模型的质量、成本和接入工作量，为是否试点接入提供依据。

当前主方案采用 **GPT-6.1 Sol high**，单次生成上限 **32768 token**，读取超时 **180 秒**，六段正文合计 **800—2000 字**。默认只选择 Sol；其他模型保留为显式选择的对照选项。

用户确认赠送额度约 35 美元，于北京时间 2026-11-15 到期。用户后续授权执行付费验证并提供两家服务商凭据。本轮已进入真实配对实验；详细用量、失败记录和结果以同目录结果报告及 `.vision-poc/study/ledger.jsonl` 为准。凭据仅保存在 Git 忽略的 `.env.local`，文件访问权限限定为当前 Windows 用户；配置、报告与账本均不包含密钥。

## 现状与验证问题

本地基线代码为 `095529d`。现有系统使用 Streamlit、Python、requests 和 Supabase；视觉服务使用 OpenAI 兼容 Chat Completions。图片经过 `modules/chart_reader.py::process_image` 处理，最多 5 张，长边不超过 1600 px，单图不超过 1.5 MiB。提示词要求返回结论、图中依据、适用边界和六段正文，`modules/ai_report_model.py::decode_report` 校验结构与引用。

用户确认当前对照为 `qwen3.8-flash`，服务地址为 `https://dashscope.aliyuncs.com/compatible-mode/v1`。本轮对照使用其原生默认思考设置、temperature 0.3、32768 输出上限及流式 Chat Completions。2026-10-24 的 `qwen3.5-plus` 合成图历史结果仅用于流程参考，本轮重新提交完全相同的图片与业务提示。Sol high 与 Qwen 原生配置的比较支持产品方案选择，无法将差异单独归因于相同计算量下的模型能力。

需要分开回答三个问题。

1. 在完全相同的图像和业务提示下，OpenAI 能减少哪些气象判读错误？
2. 专业图与多图任务是否值得增加每份可接受报告的费用和等待时间？
3. 优势来自模型、图像分辨率、提示词还是输出约束？

JSON 合格、图片引用有效和导出成功属于工程指标；气象事实正确与证据匹配由人工核对。

## 最小技术范围

沿用项目 Python 3.12 环境及已安装的 Pillow、requests、Streamlit，不新增框架或依赖。脚本在 `tools/vision_poc.py`，配置在 `tools/vision_poc_config.json`，运行材料默认存放于 Git 忽略的 `.vision-poc/`。

脚本复用生产图片预处理、提示词、输出解析和结构校验。HTTP 调用在独立实验入口完成，按模型适配参数。生产调用固定传 `temperature=0.3`、`max_tokens`；选用 GPT-6 推理模式时应移除 temperature，并使用适配后的输出限额参数。Qwen 使用流式 Chat Completions；Sol 在开发集出现约 61 秒的无回执连接失败后，改用 Responses 后台请求，一次创建、立即保存 response ID、轮询同一响应。后台轮询窗口为 180 秒，各 HTTP 请求读取超时为 180 秒；对同一 response ID 的临时 GET 故障最多连续尝试 3 次，不重发生成 POST；180 秒并非严格的端到端耗时上限。轮询超时继续保留预算与 response ID，后续只读取同一响应，不自动重新生成。不涉及工具调用或生产系统迁移。

实验提示词在生产提示词后追加统一长度要求。正文长度是 `sections` 六个 `body` 去除空白后的 Unicode 字符数，含标点、数字和英文字母，不计标题、JSON 键名及 findings/evidence/limitations 字段。返回后离线校验该计数，低于 800 或高于 2000 标为 `body_length_failed`，保留回答和用量，不自动补写或再次请求。图不可判读时优先据实说明，允许短答被标记，避免凑字数。生成 token 上限同时容纳推理、正文和非可见格式 token，字符长度与 token 用量分别管理。

离线评测不写 Supabase，也不消耗应用用户配额。通过后再安排 2 至 3 次受控的工作台集成验收，核验预留释放、错误展示、引用和下载无重复调用。

## 候选模型与额度预算

截至 2026-11-04 官方 Standard、短上下文价格，单位为美元/百万 token。

| 模型 | 角色 | 输入 | 输出 |
| --- | --- | ---: | ---: |
| `qwen3.8-flash` | 全样本对照，原生思考 | 约 0.119083 | 约 0.401905 |
| `gpt-6.1-terra` | 可选低成本对照，需显式选择 | 1 | 5 |
| `gpt-6.1-sol` | 默认主模型，high，全样本 | 2 | 10 |
| `gpt-6-astra` | 可选困难案例对照，需显式选择 | 10 | 50 |

官方模型定位用于确定候选；本轮已验证 Sol 与 Qwen 可调用。Qwen 北京地域原生标价为输入 0.8 元、输出 2.7 元/百万 token；表中美元仅按配置记录的参考汇率 6.7180 元/美元换算，用于统一预算，实际支付及免费额度以阿里云账单为准。Terra、Astra 未调用。

Sol 使用 high 思考度，Responses 参数为 `reasoning.effort=high`、`max_output_tokens=32768`；旧 Chat 适配对应 `reasoning_effort=high`、`max_completion_tokens=32768`。不传 temperature，最大允许配置值为 32768。读取超时在 `request_policy.read_timeout_seconds` 中配置为 180，连接超时仍为 10 秒。Terra、Astra 配置保留供后续另行设计对照。发生截断时先在开发样本上诊断；冻结设置后再运行留出样本。不同服务商的推理机制不同，应记录原生设置及实际总成本，不把相同 token 数当作等量计算。

举例，Sol 每次总输入为 6000 token、实际总生成量含推理为 8192、16384、24576、32768 token 时，Standard 标价估算分别约为 0.09392、0.17584、0.25776、0.33968 美元。24 个案例均实际生成到 32768 的情景约为 8.15232 美元。生成上限不等于实际消耗。这是情景测算，尚未观测真实图像用量，未包含基线服务商、重复运行、缓存写入及其他账单调整。

建议将首阶段的研究停止线设为 10 美元，只在发现具体待验证问题时扩展，全部 OpenAI 实验计划最多使用 25 美元，保留约 10 美元作为异常、集成验收和账单差异余量。证据充分时提前结束。现有模型的调用由其服务商另行计费，OpenAI 赠送额度无法支付这些费用。

Sol 单次预算按输入预留 32768 token、生成上限 32768 token 计算，输入费率按 2.5 倍预留，以覆盖所核对价格中的较高缓存写入费率。调用前资金预留为 `(32768 × 2 × 2.5 + 32768 × 10) / 1000000 = 0.49152 美元`。输入预留是保守规划参数，尚未证明是任意图像的严格上界。未知用量保留全部资金预留；已知用量取“输入按保守费率估算”与“未缓存标价估算加 25% 余量”中的较大值用于预算占用，账单估计另行记录。两种算法都只计算一次完整生成量，推理不重复相加。

24 个 Sol 案例的全部初始预留之和为 11.79648 美元。默认研究停止线仍为 10 美元，不会自动提高；成功返回后按已知用量重新计算占用，因此预留之和不等于最终费用。若下一次预留无法容纳，脚本在发请求前停止，可根据实际记录再决定是否调整研究预算。单个研究目录累计预留跨重启保留，本地预算参数最高允许 30 美元。实际运行仍应使用独立项目、平台硬支出限额及账单核对；平台限额生效存在延迟。输入用量超出预留边界时脚本停止后续调用。

`--budget-usd` 管理同一研究目录下全部服务商的合计预留；OpenAI 赠送额度另按 `provider_costs` 中的 OpenAI 小计及平台账单核对。

最终费用以各服务商账单为准。脚本 `estimated_usd` 按未缓存输入及完整输出的 Standard 标价估计，缓存读写、折扣、汇率和区域附加费可能造成差异。推理 token 已包含在输出中，绝不重复相加。

## 24 个真实案例

实验单位为一个“问题加 1 至 5 张图”的案例。至少来自 6 个不同天气过程；同一过程的相邻时次、同一图的清晰/模糊版本均置于同一数据划分，避免信息泄漏。

| 类别 | 案例数 | 开发/留出 | 核验重点 |
| --- | ---: | ---: | --- |
| 工作台曲线和统计图 | 4 | 1 / 3 | 坐标、单位、极值、累计量与瞬时量 |
| 地面及高空形势图 | 6 | 2 / 4 | 层次、时效、槽脊、系统位置、等值线 |
| 雷达图 | 4 | 1 / 3 | 色标、回波位置和强弱、缺失图例 |
| 卫星云图 | 4 | 1 / 3 | 通道、亮温与云顶特征、图上可支持的判断 |
| 多图综合 | 6 | 1 / 5 | 2 至 3 时次演变、跨层次配合、跨图矛盾与时间对齐 |

多图案例可适当补充 5 图输入的工程边界检查。模型能力统计以实际案例为单位，重复请求用于稳定性核验，不增加独立天气案例数。

来源优先选官方气象机构公开发布的天气分析、雷达和卫星材料，以及工作台由已知数据生成的曲线。每个案例保存原图、来源 URL、访问时间、图上有效时间/时区、图种/层次、处理前后哈希、参考事实、允许误差和人工复核人。公开可查看不自动意味着允许再分发，运行素材默认保存在被忽略目录中。

已完成 24 个真实公开案例，包含 13 个事件组、32 张提交图像，6 个开发案例与 18 个留出案例之间没有同事件交叉。曲线由 Open-Meteo 提供的 ERA5 再分析生成，不能称为气象站实测。专业图来自 NOAA/NWS/WPC 和 JMA；原始图、来源、转换说明及哈希保存在 `.vision-poc/real/source_inventory.json`。参考事实由 Codex 对照原图及来源预先编写，随后冻结清单。查看 radar_02 回答后重新核查原图发现两处色标缺失记录错误，另存 `reference_errata.json`，原冻结清单不变；勘误对所有模型一致生效，并随盲评包提供。独立气象专家复核仍待完成。`status=pending` 或 `reference_reviewed=false` 时脚本拒绝运行。参考答案在查看候选模型输出前完成复核；含数值时区分明确标注的准确值、按色阶估计的区间及图面不可读的值。清晰标注按标注精度判分，色阶读数按预先登记的色阶区间判分。

## 运行方式

以下 PowerShell 命令为离线操作示例，从项目根目录执行。已有 demo 和真实清单应保留，请对新演示使用新目录，避免覆盖冻结参考。无需密钥，也不发送 API 请求。

```powershell
.\.venv\Scripts\python.exe -B tools\vision_poc.py demo --out .vision-poc\demo-new
.\.venv\Scripts\python.exe -B tools\vision_poc.py run --manifest .vision-poc\demo-new\manifest.json --out .vision-poc\study
.\.venv\Scripts\python.exe -B tools\vision_poc.py template --out .vision-poc\template-new.json
```

`run` 默认只选择配置中 `default_models=["sol"]`，只生成 `plan.json`，包括 high 思考度、32768 生成上限、180 秒读取超时、800—2000 字要求、处理后尺寸、字节数、原图/提交哈希和预算预留。运行过 demo 后应保留该目录；再次创建请换目录，工具拒绝覆盖已有演示材料。

实测时复用用户授权的现有密钥，通过当前进程环境中的 `OPENAI_API_KEY` 提供给 OpenAI。基线使用 `BASELINE_VISION_API_KEY`，当前配置已填写基线模型、HTTPS 地址及参考价格。不要把密钥放进配置 JSON、命令参数、样本说明或参考答案。工具不自动读取 `.env` 或 Streamlit Secrets。

下面两条命令 **会产生实际 API 费用**。本轮已执行开发与留出实验，同一配置的账本可防止重复提交；改动配置将生成新任务，不能用重新运行替代无费用的报告查看。`--limit` 限制当前命令新增请求数，累计预算仍读取同一账本。生产请求参数若需调整，请先在开发集诊断，禁止看完留出答案后反复挑提示词。

```powershell
.\.venv\Scripts\python.exe -B tools\vision_poc.py run --manifest .vision-poc\real\manifest.json --models sol baseline --split dev --out .vision-poc\study --budget-usd 10 --limit 3 --live
.\.venv\Scripts\python.exe -B tools\vision_poc.py run --manifest .vision-poc\real\manifest.json --models sol baseline --split holdout --out .vision-poc\study --budget-usd 10 --live
```

先补齐并复核开发集，再补齐留出集；`--split` 只校验选中部分。模型/提示词/推理设置冻结后，两组都应完成，必要时先续跑开发集。用 `--models baseline sol` 选择配对，相同输入和配置的已完成任务会跳过。`--workers 2` 最多同时运行两个请求，仍由主线程逐次写入预留后派发，发生异常后结算正在运行的任务并停止新派发。`--models astra --cases ...` 可选择预先指定的困难案例作额外对照。`--repeat 2` 在保留 trial 1 的基础上添加 trial 2，适合对预先选定的 3 个真实困难案例检查波动。

脚本用内容、提示词、模型配置、超时/长度策略和 trial 生成任务标识，报告也按这组配置分别汇总。相同任务在同一研究目录中不会重复提交；中断、超时和 HTTP 错误的任务也不会静默重试。每次请求先把预留写入 `ledger.jsonl` 并刷盘，随后才访问服务。HTTP/不确定失败立即停止，连续两次输出契约失败也停止。不得通过更换输出目录绕开原账本；改模型配置、提示词或请求策略会构成新的付费任务。

因进程崩溃而保留 `run.lock` 时，应先确认原进程已退出，再处理锁文件；账本中 started 记录继续保留预算。脚本不提供自动释放未知用量的功能。错误记录不保存异常原文或服务商错误正文，避免把请求体和凭据写进日志，保留状态及可用的 Request ID。后台请求的读取失败或等待未完成，可用 `python tools/vision_poc_recover.py <case_id>` 对原 response ID 发起一次 GET；该辅助入口从 `.env.local` 读取 OpenAI 凭据，保持原图及提示哈希一致，只追加结算事件，永不创建新生成请求。待完成时预算保持，已完成时仍保留原始故障历史。

默认实测窗口在北京时间 2026-11-14 00:00 关闭，预留至少一天缓冲。用户仅给出了 11 月 15 日的日期，尚未核对平台精确到期时刻。修改该窗口前重新核对平台余额和到期信息。

## 评分与接入判据

每份回答按五个维度各 0 至 20 分评分：图种/时间/层次、图例与单位、数值及位置、天气系统与演变、依据与判断范围。一般锚点为 20 分正确完整、15 分小遗漏、10 分有实质缺漏、5 分存在明显错误、0 分核心判断错误。细分事实与数值允许误差写入各案例参考答案。单图的演变项检验模型是否正确识别信息范围；不能借此要求编造移动方向。

改变业务结论的单位、时效、移动方向错误，无依据的极值/地点、将单图推导为确定预报或发布级预警，登记为严重错误。严重错误直接判该份回答不可接受，即使总分较高。

实测后，脚本生成以下材料。

- `blind_review.json`：打乱顺序的原图路径、问题、参考答案及回答，不含模型标识。
- `reviews.csv`：按 blind_id 填五项分数、严重错误 yes/no、可接受 yes/no、复核人、`review_method` 及意见。
- `private_mapping.json`：模型与盲评编号的对应关系，评分完成前不交给评分人。
- `summary.json`：按模型配置与请求策略、合成/真实、开发/留出及图类分别统计结构完成数、正文长度检查/通过数、完整输出契约通过数、人工评分、严重错误、用量估算、耗时和每份可接受报告成本；分别列出各服务商费用，输出 trial 1 的逐案例配对胜/平/负。输入哈希或提示词不相同时不配对；同一案例/模型别名有多个配置时标记为歧义，保留原始记录供复核。

填写评分后可反复执行以下离线命令，已有评分会保留，未评分项不会自动算作通过。本轮 `review_method=codex_source_review` 的评分属于原图和来源辅助初审；只有明确登记为 human 且全部完成时，汇总才将 human_reviewed 标为 true。

```powershell
.\.venv\Scripts\python.exe -B tools\vision_poc.py report --out .vision-poc\study
```

“可接受报告”同时要求状态为 ok、结构与结束原因合格、正文长度在 800—2000 字内、人工总分至少 80、无严重错误且人工接受。每份可接受报告成本以该组所有已知调用成本除以可接受份数，包含同组失败的已知费用；评分不全或存在未知用量时不输出该比值。合成样本与真实样本、开发集与留出集分别展示。盲评仍可能受到模型自报身份或文风影响，应先核事实、再判断可读性；抽取至少 6 个案例做第二次人工复核。

建议在采样前登记以下试点门槛。它们是本项目的初始决策规则，需要与业务容错要求一起解释。

1. 18 个真实留出案例至少 16 个可接受，专业图及多图中的严重错误为 0。
2. 与当前模型相比，至少多通过 2 个留出案例，或在事先登记的某一困难图类有明确增益。
3. 每份可接受报告估计成本以 0.10 美元作为经济性目标，实测 P95 耗时以 75 秒作为交互目标。high 方案按实测报告质量、费用与耗时的取舍；180 秒是验证脚本读取超时，生产读取超时仍为 90 秒。生成上限不代表每次必然使用全部 token，验证脚本的等待容忍度也不代表生产界面已接受该等待时间。
4. 结构问题、预留结算、引用或导出尚有故障时，先修工程链路再评价试点条件。

达到门槛可以进入少量受控试点。只在多图任务有优势时提供人工选择的增强解读入口，复用现有默认模型；效果接近时优先保留成本更低、运行更稳的方案。若所有模型都在细小标注处失败，先检查 1600 px 预处理损失，再在开发样本上试“全图加局部裁切”。裁切比较使用匹配输入重新运行各候选，避免把输入改进计为模型增益。

24 个案例用于发现主要错误类型并选择试点方向，无法据此估计罕见严重错误率或对全部气象场景给出精度承诺。报告列出逐案例配对胜/平/负、通过数和具体错误，减少对单一平均分的依赖。真实图可由不同专家作出合理解释时，参考答案登记允许的解释集合。
