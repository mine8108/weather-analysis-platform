# 气象数据交互分析平台 · 用户使用手册

本手册是平台使用说明的唯一真相源，共 14 章。手册正文由应用现场读取与导出，不另行维护副本。侧边栏的「📖 用户使用手册」按钮可在应用内阅读同一份内容，并导出为独立 HTML 文件；导出的文件页头会自动写入当前应用版本与生成时间，因此本手册正文不出现任何硬编码版本号。

## 1. 这份手册怎么用

本手册同时服务三类读者，三者的阅读路径不同，请按自己的目的选一条走，不要从头到尾顺序读。

**路径 A · 评审 / 老师**：先读第 2 章（能力与边界）与第 14 章（标准引用与术语表），这两章集中回答「这个平台做了什么、依据是什么、哪些事它明确不做」。随后按第 4 章（界面总览）过一遍 6 个 Tab 的职责，再挑第 6 章（可视化）、第 7 章（数值预报）、第 9 章（报告导出）中任意一章看具体呈现。第 8 章（AI 读图解析）与第 11 章（ERA5）是本平台区别于普通绘图工具的两块能力，建议一并翻阅。

## 2. 平台能力与边界

**平台能做的八件事**（每一件都能在源码中定位到实现）：

1. 数据导入：CSV / Excel 上传、网页逐条手动录入、Open-Meteo 在线接口按经纬度与时段拉取，三者可混用并按时间戳拼接。
2. 列名归一化：把中英文列名别名自动映射为平台的标准字段名，映射表在 `config.FIELD_ALIASES`。
3. 时间智能识别：从列名、多列拼接、内容模式三层识别时间列，必要时让你手动指定，完全找不到时才用序号生成时间轴。
4. 数据质量控制：物理量范围校验、时间一致性检测、完整性检查，输出百分制质量评分。
5. 可视化分析：7 个可切换的图表子面板，覆盖综合看板、风场、要素关系与相关性、统计摘要与多站点对比、要素分布、空气质量、双要素时序。
6. 数值预报：接入 Open-Meteo 的 GFS 预报（免注册），含逐时时间图、国标 AQI 预报、72 小时高温面板、风玫瑰、7 项生活出行指数与预报验证。
7. 报告导出：按观测数据与预报数据的有无自动组织章节，输出专业版与通俗版两种 Word 报告，并支持数据与预报的 CSV 导出。
8. 报文解码：粘贴 SYNOP 或 METAR 报文，解析为平台字段并可直接并入手动录入区。

**平台明确不替代国家气象部门权威预报。** 侧边栏页脚固定显示这句声明：「※ 本平台分析结果仅供学习参考，不替代国家气象部门权威预报。」平台做的是把已有观测数据与公开数值预报做统计、匹配与呈现，不发布预警信号，不承担预报服务责任。界面上的「预警信号」是按《气象灾害预警信号发布与传播办法》阈值自动匹配出的参考结果，正式预警以中国气象局及各级气象台发布为准。

**数据来源与注册要求**：

| 数据 | 来源 | 是否需要注册 |
|---|---|---|
| 历史气象观测 | Open-Meteo Archive API | 不需要，接口无密钥 |
| 实时天气（首页天气墙） | Open-Meteo Forecast API | 不需要 |
| GFS 数值预报 | Open-Meteo Forecast API（GFS 模式） | 不需要 |
| 空气质量 / 大气成分预报 | Open-Meteo Air Quality API（CAMS） | 不需要 |
| ERA5 再分析 | Copernicus Climate Data Store | 需要免费注册，且必须本人手工接受数据集许可 |
| 平台登录与云端数据 | Supabase（邮箱密码 + 行级安全） | 必须登录后才能进入主程序；注册需管理员发放邀请码 |

**边界清单**（这些事平台不做，避免误解）：

- 不做数据同化与模式订正，GFS 预报值原样呈现，只有预报验证区块给出误差统计。
- 不代下载 ERA5。CDS 的数据集许可只能由账号本人在网页上接受，平台只交付可在本机运行的脚本包，全程不接触你的 CDS 凭证。
- 不落盘保存上传的图片，读图解析的图片只在内存中处理。
- 不做图片型报告，Word 报告以表格与文字排版，交互式图表请回应用界面查看。
- 不保证第三方接口长期不变。Open-Meteo 与 CDS 都可能调整接口或限流，平台已做重试与降级，但可用性最终取决于上游。

## 3. 安装与启动

### 3.1 环境与依赖

`runtime.txt` 声明 Python 3.12，本地建议 Python ≥ 3.11。`requirements.txt` 中除 Supabase 客户端外全部锁定版本：

| 包 | 版本 | 用途 |
|---|---|---|
| streamlit | 1.59.1 | Web 界面框架 |
| pandas | 3.0.3 | 数据处理 |
| numpy | 2.5.1 | 数值计算 |
| plotly | 6.8.0 | 交互式图表（可导出 HTML） |
| openpyxl | 3.1.5 | 读取 .xlsx |
| python-docx | 1.2.0 | 生成 Word 报告 |
| requests | 2.34.2 | 调用 Open-Meteo 等外部接口 |
| supabase | ≥ 2.0.0（未锁小版本） | 登录与云端数据集 |

### 3.2 本地启动步骤

1. 打开终端（Windows 可用 `Win + R` 输入 `cmd`，或从开始菜单打开 PowerShell；macOS 用「访达 → 应用程序 → 实用工具 → 终端」）。
2. 进入项目目录：`cd weather_app`。
3. 安装依赖：`python -m pip install -r requirements.txt`。
4. 复制 `.streamlit/secrets.toml.example` 为 `.streamlit/secrets.toml`，按 3.3 填写密钥。
5. 启动应用：`streamlit run app.py`。
6. 终端会打印本地地址，默认 `http://localhost:8501`（端口来自 `.streamlit/config.toml` 的 `port = 8501`）。浏览器打开该地址即可。

注意：`pip install` 与 `streamlit run` 是终端命令，必须在外层命令行里执行；把它们写进 `.py` 文件再用 IDE 运行不会生效。

### 3.3 密钥配置

平台在渲染主界面之前先做登录门禁，未登录只能看到登录页，因此 Supabase 两项密钥是启动的硬前提。

| 键 | 是否必填 | 缺失时的行为 |
|---|---|---|
| `SUPABASE_URL` | 必填 | 登录页显示「未配置 Supabase 密钥」并给出写入位置，随后停止渲染 |
| `SUPABASE_ANON_KEY` | 必填 | 同上 |
| `SUPABASE_SERVICE_ROLE_KEY` | 选填 | 服务端管理客户端静默禁用：邀请码授权注册与管理员面板不可用，其余功能正常 |
| `ADMIN_PASSWORD` | 选填 | 登录页底部「管理员入口」提示未配置，无法解锁 |
| `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` | 选填 | 文本 AI 解读能力降级为结构化摘要，不报错 |
| `LLM_VISION_MODEL` / `LLM_VISION_API_KEY` / `LLM_VISION_BASE_URL` / `LLM_VISION_MAX_TOKENS` | 前三项选填、模型名必填 | 读图解析视为「未配置」，页面给出配置指引且不显示生成按钮（详见第 8 章） |

**注册方式**：公开注册在 Supabase 侧已关闭，平台采用邀请码授权注册。管理员在登录页底部「管理员入口」输入 `ADMIN_PASSWORD` 解锁后生成一次性邀请码，用户注册时填入邀请码，由服务端建账号并自动登录。邀请码在数据库中只存 SHA-256 摘要，不存明文。

### 3.4 启动期故障对照

| 现象 | 原因 | 处置 |
|---|---|---|
| 页面报「缺少依赖 supabase」 | 环境未安装 supabase 客户端 | `python -m pip install -r requirements.txt` 后重启应用 |
| 页面报「未配置 Supabase 密钥」并停止 | `secrets.toml` 缺失或键名为空 | 在 `.streamlit/secrets.toml`（或 Streamlit Cloud 的 Settings → Secrets）填写 `SUPABASE_URL` 与 `SUPABASE_ANON_KEY` |
| 页面报「DNS 解析失败」 | URL 不完整、带多余空格、带了 `/rest/v1/` 路径，或项目刚创建 DNS 未生效 | 核对 URL 是否形如 `https://项目标识.supabase.co`；新项目等待 3–5 分钟；去掉末尾路径与空格 |
| 浏览器打开 8501 无响应 | 端口被其他程序占用，或应用已在别的端口启动 | 查看终端实际打印的地址；必要时改 `.streamlit/config.toml` 的 `port` |
| 依赖安装报网络错误 | 内网代理或镜像源不可达 | 换镜像源或配置代理后重装，应用本身无需联网安装 |
| 天气预报区提示「请求过于频繁（429）」 | Open-Meteo 免费接口有限速，短时间重复拉取触发 | 等待退避重试（平台自动重试 2 次并提示剩余次数）；减少连续刷新；天气墙有 10 分钟缓存 |
| 数值预报区未配置 Supabase 缓存时较慢 | 二级缓存表 `gfs_cache` 不可用时只走会话缓存 | 属正常降级，不影响结果正确性 |

## 4. 界面总览

### 4.1 页面结构（自上而下）

1. **登录门禁**：未登录时只渲染登录/注册页，登录后才进入主程序。
2. **主标题与副标题**：副标题列出平台主线功能。
3. **下一步提示条**：根据当前状态给一条建议。无数据时提示先导入；有数据无预报时推荐进入可视化；有数据且有预报时推荐进入报告导出，并提示可查看读图解析。
4. **数据摘要卡**（有数据时显示）：显示数据来源、时间范围、记录数、已识别的气象要素与污染物字段；同时提供数据时间范围筛选器（按日期区间过滤全站使用的数据）、三个跳转按钮、以及「💾 保存到云端」。
5. **Tab 导航**：6 个标签，横向 radio 实现，支持程序化跳转。
6. **Tab 内容区**。

**摘要卡跳转按钮的行为**：三个按钮分别为「📊 图表」「🖼 读图」「📤 导出」，对应 Tab 索引 1 / 3 / 4；当前所在 Tab 的同名按钮会自动隐藏，避免原地跳转。跳转走统一的导航栈：入栈当前 Tab，栈深最多保留 10 层，供「← 返回」类按钮回退。

**天气墙封面**：当没有导入任何数据时，主区显示封面页天气墙，默认预置全国 34 个省级行政区的省会 / 首府 / 直辖市，首页最多同时展示 6 张城市卡片，可搜索城市、按定位添加、删除与刷新。天气数据来自 Open-Meteo，缓存 10 分钟；空气质量缓存 30 分钟。已有数据时侧边栏提供「☁️ 天气墙封面」按钮可随时回到封面，封面页也有「📊 返回数据视图」按钮切回摘要卡。

## 5. 数据导入与质量控制

### 5.1 三种导入方式

| 方式 | 入口 | 支持内容 | 关键限制 |
|---|---|---|---|
| 上传文件 | 「📁 上传文件」/「[文件] 文件导入」 | CSV（含 .txt）、Excel（.xlsx / .xls） | 单文件原始大小 ≤ 20 MB；xlsx 解压后总体积 ≤ 200 MB（防压缩炸弹） |
| 手动录入 | 「✏️ 手动录入」/「[编辑] 手动录入」 | 逐条填写时间、气温、气压、湿度、风速、风向、总云量、能见度、降水量、天气码、站点 ID | 时间字段必填，其余留空即不写入该条记录 |
| API 获取 | 「🌐 API获取」/「[网络] API 数据获取」 | 三个子标签：Open-Meteo（气象）、Open-Meteo（空气质量）、ERA5（CDS 引导） | 气象与空气质量均免注册；日期范围必须选满起止两天；ERA5 需按第 11 章操作 |

Open-Meteo 气象接口一次拉取的要素为：气温、相对湿度、地面气压、10m 风速、10m 风向、云量、降水、天气码，时间区固定为 `Asia/Shanghai`，结果自动写入 `station_id = API(纬度,经度)`。空气质量接口拉取 PM2.5 / PM10 / SO₂ / NO₂ 四项逐时浓度。两个接口都提供「[使用] 使用并合并气象+空气质量」按钮，按时间戳做左连接；若两条数据时段完全不重叠，界面会提示并只保留气象数据。

### 5.2 向导路径与跳走向导路径

Tab 0 有两条并存的路径，功能等价，区别只是界面组织方式。

**向导路径**（默认）：

| 步骤 | 内容 | 可执行动作 |
|---|---|---|
| 第 0 步 | 「选择数据导入方式」，三个大按钮 | 选文件 / 选手动 / 选 API |
| 第 1 步 | 所选方式的具体输入区 | 导入成功后自动进入第 2 步；可「← 返回选择方式」 |
| 第 2 步 | 数据预览与质量检查 | 三个指标卡「记录数 / 缺失率 / 疑似异常值」，预览前 10 行，随后渲染质量控制报告；底部三个按钮「✅ 确认数据，前往可视化分析」「← 返回上一步」「🔄 重新导入」 |

第 2 步的「疑似异常值」口径是固定两条规则：气温 > 55 ℃ 或 < −50 ℃、湿度 > 100 % 或 < 0 %，两者命中数相加。它是快速提示，不等同于第 5.5 节的完整质控结论。

「🔄 重新导入」会清空数据、来源、预警列表、质量评分、预报结果、导入历史与时间筛选，回到第 0 步。

**跳走向导路径**：点击右上角「跳过向导」，界面切换为三个子标签「[文件] 文件导入」「[编辑] 手动录入」「[网络] API 获取」，三者同时可用，适合需要交替使用多种方式或反复追加记录的用户。该路径下方同样渲染数据量、数据来源与质量控制报告，并可「🔄 返回向导模式」。

**手动录入的追加语义**：在两条路径下，手动录入的新记录都会与现有数据按 `timestamp` 合并并重新升序排序，而不是覆盖。

### 5.3 列名别名与标准字段

导入后的第一步是列名归一化：逐个列名去除首尾空格后，与 `config.FIELD_ALIASES` 的别名做**不区分大小写**的等值比较，命中即改名为对应的标准字段名。支持中文、英文与常见缩写混用，例如「温度 / 气温 / temp / t2m / 2m_temperature」都映射为 `temperature`，「PM2.5 / pm2_5 / 细颗粒物」都映射为 `pm25`，「时间 / 观测时间 / valid_time / datetime / Unnamed: 0」都映射为 `timestamp`。

平台标准字段共 18 个，也是字段识别详情里「已识别标准字段」的判定依据：

| 字段 | 含义 | 单位 |
|---|---|---|
| timestamp | 时间 | 时间戳 |
| temperature | 气温 | ℃ |
| pressure | 气压 | hPa |
| humidity | 相对湿度 | % |
| wind_speed | 风速 | m/s |
| wind_direction | 风向 | ° |
| cloud_cover | 总云量 | 成（0–10） |
| visibility | 能见度 | km |
| weather_code | 天气现象码 | WMO 整数码 |
| precipitation | 降水量 | mm |
| station_id | 站点编号 | 文本 |
| longitude / latitude | 经度 / 纬度 | ° |
| so2 / nox / tsp / pm25 / pm10 | 大气污染物 | μg/m³ |

未识别的列会被列在「未识别字段」中，不参与分析与预警，也不会导致导入失败。

**标准模板**：点击「[下载] 下载标准数据模板 (CSV)」得到 `气象数据模板.csv`，表头为 `timestamp, temperature, pressure, humidity, wind_speed, wind_direction, cloud_cover, visibility, weather_code, precipitation, station_id`。

### 5.4 时间列识别顺序

平台按 L1 → L5 逐级尝试，任一级成功即停止：

1. **L1 列名匹配**：分 5 个优先级梯队匹配列名，从 `timestamp / 时间 / 日期 / datetime` 一直到最低优先级的 `day / hour / month / year`。已是 datetime64 类型的列直接采用。
2. **L2 多列拼接**：识别到 `year + month`（可选 `day`、`hour`）多列组合时拼接解析，有效值不少于总行数的一半才采用。
3. **L3 内容模式扫描**：抽样前 30 行，按 ISO 日期时间、斜线日期、紧凑型 `YYYYMMDDHH` / `YYYYMMDD` 等模式匹配，命中率 ≥ 60 % 才采用。
4. ****HHMMSS 数值码**：若某数值列取值落在 0–240000、字符串长度 4–6 位且半数以上能按 `%H%M%S` 解析，则按「今天 + 该时刻」生成时间戳，并在摘要卡上只显示时分。
5. **L5 交互确认**：以上都失败时，按「像日期的程度」排序列出候选列让你选择；你选择「（不使用时间轴）」或没有候选时，用序号生成时间轴并给出提示。

解析完成后会显示一条时间报告：识别方式、有效条数 / 总条数、缺失条数、最常见步长与时间跨度。若某列的有效识别率低于 30 %，平台会警告并再次给出列选择器。

### 5.5 质量控制：四项指标与评分口径

导入完成后默认渲染质量控制报告，它由三项检查合并出的**四类问题**构成：

| 问题类型 | 触发条件 | 严重度判定 |
|---|---|---|
| 范围异常 | 超出字段有效范围（见下表） | 超出比例 > 5 % 记为 error，否则 warning |
| 时间乱序 | 时间列非单调递增 | 固定 warning（数据会被自动排序） |
| 数据突跳 | 相邻**逐时**记录变化超过阈值：气温 ≥ 8 ℃、气压 ≥ 10 hPa、湿度 ≥ 30 %。步长必须在 0.5–1.5 小时之间，且按站点分组比较 | 固定 warning |
| 数据缺失 | 除站点编号外的任一列存在缺失 | 缺失率 > 30 % 记 error，> 10 % 记 warning，其余 info |

字段有效范围：气温 −50 ~ 55 ℃、气压 500 ~ 1100 hPa、湿度 0 ~ 100 %、风速 0 ~ 75 m/s、风向 0 ~ 360 °、云量 0 ~ 10 成、能见度 0 ~ 100 km、降水 0 ~ 500 mm；SO₂ / NOx / PM2.5 各 0 ~ 500 μg/m³，TSP / PM10 各 0 ~ 1000 μg/m³。

**评分口径**：从 100 分起扣。每条问题扣 `严重度权重 × min(该问题条数 ÷ 总行数 × 10, 5)`，权重为 error 5 分、warning 2 分、info 1 分，结果下限为 0，保留一位小数。因此同一条问题最多扣 5 分，但问题条数越多扣分越接近上限。

**评分分级**：≥ 90 分显示为「数据质量：优秀」；70 ~ 89 分显示为「数据质量：一般」；< 70 分显示为「数据质量：较差，建议检查」。该评分会写入会话状态并出现在 Word 报告的封面上（数据质量评分 X/100）。报告在数据导入前生成为 0 分，属正常。

报告同时显示「总记录数」与「有效字段数」（不含站点编号）。

### 5.6 导入异常对照

| 现象 | 原因 | 处置 |
|---|---|---|
| 「文件过大（X MB），上限 20 MB」 | 单文件超过 20 MB | 先在本地裁剪行数或按列拆分后分次导入 |
| 「Excel 内容过大（解压后约 X MB），上限 200 MB」 | xlsx 解压后超限 | 另存为 CSV 后导入 |
| 「Excel 文件格式无效（不是有效的 xlsx 文件）」 | 文件实为 .xls 或已损坏 | 用 Excel / WPS 另存为规范 .xlsx 或导出 CSV |
| 中文列名变成乱码 | CSV 编码不是 UTF-8 | 平台会依次尝试 UTF-8、GBK、GB2312、GB18030、latin-1；仍乱码时请另存为 UTF-8 |
| 提示「未检测到时间列，已用序号生成时间轴」 | 时间列既未按名称命中，内容也不符合任何日期模式 | 在列选择器中指定时间列，或按第 5.4 节规范整理数据 |
| 只识别出个别字段 | 列名不在别名表内 | 参照第 5.3 节的标准字段表改名后重新导入 |
| 质控报告出现大量「范围异常」 | 单位口径不一致（例如气压写成 Pa、降水写成 m） | 换算为单位匹配的数值后重新导入 |

## 6. 可视化分析怎么读

Tab 的副标题为「[图表] 可视化分析」。页面顶部是一个「图表模块」下拉选择器，共 **7 个子面板**，任一时刻只渲染当前选中的那一个。所有图表都通过统一的受保护渲染出口绘制：正常时图表下方附带「📥 导出 HTML」按钮（文件名取该图的区块名），渲染失败时只报告该图失败并给出通俗原因，不会让整页白屏；开启调试模式后可展开完整报错。

### 6.1 综合看板

2×2 四联图：气温（含样本数不少于 5 时叠加的 5 日滑动均温虚线）、气压、相对湿度、风速（柱状）。

判读要点：先看气温与气压的同步关系，气压持续下降常伴随天气转坏；再看湿度与气温的反相特征；风速柱状图的突增段往往对应气压曲线的剧烈变化。若数据缺少其中任一要素，页面会明确列出缺失字段名并说明对应子图将为空。

### 6.2 风场分析

左列是风向风速玫瑰图：按 16 个方位扇区分桶，每个扇区按风速分 9 档堆叠——静风、软风、轻风、微风、和风、清风、强风、劲风、大风及以上，配色由浅至深，第 6 档（强风）起转为警示色系；径轴读数为该风向的出现频次，角度标注为 16 方位缩写。

右列是风速时间序列，以及两个指标：「平均风速」附带蒲福风级名与级数，「主导风向」附带出现次数与占比。判读时注意玫瑰图给的是**风的来向**：扇区指向北说明北风，即风从北方吹来。主导风向占比越高，该地风向越稳定；若各扇区长度接近，说明风向多变，单一风向结论不可靠。

### 6.3 要素关系

三块内容自上而下：

1. **要素间散点矩阵**：候选要素为气温、气压、湿度、风速、SO₂、NOx、PM2.5、PM10，按数据实际存在情况最多取前 6 个；对角线是各自的分布直方图，非对角线是两两散点。图上每个点都做了抽稀（最多 1500 点），因此密集区只能看趋势形状，不能数点数。
2. **单要素时间序列**：可在气温、气压、相对湿度、风速、能见度、降水量及五项污染物中任选一项看逐时曲线。
3. **全要素相关性热力图** + **相关性分析解读**：热力图用 Pearson 相关系数，红色为正相关、蓝色为负相关，格内直接标注数值。下方解读按 |r| 降序列出**前 8 组**配对的强度分级：|r| ≥ 0.7 为强，≥ 0.3 为中等，其余为弱，并标注正负方向。

判读要点：相关性只说明同步变化，不说明因果；样本量少或存在强日变化时，相关系数容易被共同的时间趋势抬高，建议先看散点图是否呈单调带状，再看 r 值。

### 6.4 统计摘要

上半部分是所选要素的描述统计表，行标签依次为总数、均值、标准差、最小值、25 % 分位、50 % 分位、75 % 分位、最大值，统计对象是气温、气压、湿度、风速、能见度、降水、云量与五项污染物中实际存在的列。

下半部分是**多站点对比**，仅当数据含 `station_id` 且站点数不少于 2 时出现。「站点管理」折叠区提供全选、取消、反选三个快捷按钮与站点多选；少于 2 个站点时会提示「请至少选择 2 个站点进行对比」。对比要素可选气温、气压、湿度、风速、能见度，图下方给出各站点的均值、最大、最小与记录数摘要表。

判读要点：多站点对比要求各站时段一致，否则曲线长度不齐属于数据问题而非天气差异。

### 6.5 要素分布

要素分布直方图，默认展示降水量，可在 12 个候选要素（降水、气温、湿度、风速、气压、能见度、云量、SO₂、NOx、TSP、PM2.5、PM10）中多选叠加，每项 30 个分箱、半透明叠加显示。适合回答「这场雨是零星小雨还是集中在少数几个时次」「PM2.5 的高值尾巴有多长」这类问题。

### 6.6 空气质量

按实际存在的污染物生成多条浓度时间序列（PM2.5 / PM10 / SO₂ / NOx），每条叠加一条同色的限值虚线：PM2.5 为 50、PM10 为 100、SO₂ 为 100、NOx 为 60，单位 μg/m³，对应二级标准日均限值口径。图下方是统计摘要表，逐项给出均值、峰值、标准限值、超标次数（形如 12/240）、超标率与达标状态。

判读要点：虚线是日均限值，若数据本身不是日均值，只能作为量级参照。AQI 等级与分指数口径见第 7 章与第 14 章；本面板展示的是**浓度**对比，不直接给出 AQI。

### 6.7 时序双要素

自由选择两个要素做双 Y 轴对比，或只选一个做单轴时序。控件有三：**时间聚合**（原始（不聚合）/ 3 小时 / 6 小时 / 12 小时 / 日累积）、**左轴要素**、**右轴要素**（含「无（单轴显示）」）。系统按要素性质自动选图型：降水量与风速用柱状，其余用折线；聚合方式上降水量取累计（sum），其余取平均（mean）。左右轴选择同一要素时会被拒绝并提示换一个要素。

判读要点：读双轴图先看两侧刻度，柱与线的对应关系只在同一时间轴上成立；使用日累积聚合时，降水柱从「逐时强度」变为「日总量」，量级会明显放大。

### 6.8 大数据量下的表现

当行数超过 3000 时，时间序列类图表按等间隔抽稀到 3000 点左右以保持交互流畅；散点矩阵单独抽稀到 1500 点，且变量数上限为 6。抽稀保留时间顺序与峰谷形态，但极值点可能被跳过。需要精确数值时请用统计摘要表或把数据裁到目标时段再绘图。

## 7. 数值预报

### 7.1 数据来源、时效与参数

预报数据来自 Open-Meteo 数值预报接口的 GFS 模式，免注册、免密钥。页面顶部参数区：

| 参数 | 默认值 | 范围 / 选项 | 说明 |
|---|---|---|---|
| 纬度 | 39.94 | −90 ~ 90 | 单点预报，按所选坐标取值 |
| 经度 | 116.85 | −180 ~ 180 | 同上 |
| 预报时效（天） | 7 | 1 ~ 16 | GFS 单点逐时预报最长 16 天 |
| 数值模式 | GFS 无缝混合 (gfs_seamless) | GFS 无缝混合 / 自动（默认 blend） | 「自动」使用 Open-Meteo 的默认混合模式 |

取数接口一次返回的要素为 2 m 气温、相对湿度、体感温度、降水、10 m 风速、10 m 风向、天气码与降水概率。结果同时写入会话与 Supabase 的 `gfs_cache` 二级缓存，缓存有效期 1 小时（GFS 约每小时更新一次），并对列集合做了版本标记，旧结构缓存会自动失效重拉。

### 7.2 页面区块与判读

**当前实况卡片**：展示当前小时的气温、风力（蒲福级 + m/s）、相对湿度、降水概率，以及空气质量（若 CAMS 有数据）。实况优先取 Open-Meteo 的 `current` 真实时数据，取不到时退回预报序列中当前小时所在行。

**时间图：逐时预报序列**：包含气温线、体感温度线、日温度包络带、12 小时累计降水柱、降水概率幕布、当前时刻竖线，并在图上标注预报可信度。底部缩放滑块只联动左侧气温轴，右侧降水轴不随滑块缩放，这是 Plotly 的原生行为。

**空气质量预报（国标 AQI）**：X 轴与 GFS 时间轴对齐，折线为国标 AQI，背景是六级色带，图例给出色块、等级与区间上限。数据来自 CAMS 全球大气成分预报，**最长 7 天**：当预报时效设为 8 天以上时，页面会说明重叠窗口只有前 7 天，第 8 天起曲线留空。AQI 由六项污染物（PM2.5、PM10、CO、NO₂、SO₂、O₃）按 HJ 633-2012 分指数表计算，页面底部标注所用标准版本；其中 CO 由接口返回的 μg/m³ 换算为 mg/m³ 后再代入，否则分指数会被放大约一千倍。

AQI 六级分档：

| AQI 区间 | 等级 |
|---|---|
| 0 – 50 | 优 |
| 51 – 100 | 良 |
| 101 – 150 | 轻度污染 |
| 151 – 200 | 中度污染 |
| 201 – 300 | 重度污染 |
| 301 及以上 | 严重污染 |

口径提示：PM2.5 / PM10 的国标分指数表按 24 小时均值定义，预报侧以逐时浓度近似代入，属已登记的已知局限；气态污染物使用 1 小时均值表，口径正确。

**72 小时高温预报面板**：取预报序列前 72 小时，绘制气温曲线与体感温度曲线，并叠加三条国家预警阈值参考线：高温黄 35 ℃、高温橙 37 ℃、高温红 40 ℃。面板下方按 72 小时内最高气温给出结论：达到或超过 35 ℃ 时以警示条给出最高气温、最大体感温度，并附 Rothfusz 热指数峰值；低于 35 ℃ 时以成功提示给出峰值气温。

**风玫瑰预报（全预报期）**：统计整个预报期的风向风速，16 个方位扇区、半径为该风向频率、按蒲福风级分 8 档着色（1–5 级蓝色由浅至深，6 级起转暖色）。静风（< 0.5 m/s）不绘入玫瑰，只列在图例与统计中。图下方给出主导风向（中英文名与占有效样本比例）与静风占比。读图时记住方位是风的来向。

**智能分析与建议**：给出预报期总结、四张极值卡（最高气温、最低气温、累计降水、最大风速）、按等级由高到低排列的预警信号卡片，以及多要素耦合风险条目。若预报期内未触发任何预警，会明确显示未触发。

### 7.3 生活出行指南（7 项）

| 指标 | 判据摘要 | 分档 |
|---|---|---|
| 穿衣指数 | 参考温度取体感温度与气温中偏差较大者；并按气温分档 | 厚冬装 / 初冬装 / 春秋装 / 轻便 / 夏装 / 酷热 |

| 体感舒适度 | Thom 不适指数 SSD = T − 0.55 × (1 − RH) × (T − 14) − V^(1/3) × (T − 10) / 20 | 炎热不舒适（≥29）/ 偏热（≥24）/ 较舒适（≥20）/ 舒适（15–19）/ 偏凉（≥10）/ 寒冷不舒适 |

| 紫外线 | 由天气码近似推断，晴天码且 72 小时平均气温 > 15 ℃ 判为很强 | 很强 / 强 / 中等 / 低 |
| 洗车指数 | 未来 72 小时累计降水 | 适宜 / 较适宜 / 一般 / 不适宜 |
| 晾晒指数 | 从 100 分起，按累计降水、平均湿度（> 70 % 扣分）与平均风速（加分）计算 | 非常适宜 / 适宜 / 一般 / 不适宜 |

七项指标以卡片形式按 4 + 3 排列，每张卡片给出等级、数值与一句操作建议。指标优先使用真实时实测数据，取不到时退回预报序列当前小时行。紫外线由天气码近似推断，阴天但紫外线强的少数情形会低估。

### 7.4 预报精度详情

位于智能分析与建议节内，包含四类补充信息：

- **趋势变化**：预报期前后半段平均气温之差（± 波动标准差），以及整体标准差。
- **波动程度**：以文字描述温度起伏大小。
- **连续高温**：预报期内连续达到高温阈值的天数。
- **降水强度分布**：按强度分类统计的降水摘要，并给出最大的 6 小时降水量及其出现时段；无降水时该项不显示。
- **昼夜温差与热带夜**：最大日较差（≥ 15 ℃ 时显示极值，否则显示平均日较差），以及夜间最低气温 ≥ 25 ℃ 的天数。

### 7.5 预报验证（GFS vs 实况）

位于预报 Tab 底部，折叠展开后运行，复用当前预报坐标。实况来源三选一：

| 实况来源 | 说明 |
|---|---|
| 会话观测数据（已导入 df） | 用已导入的观测数据与同期预报配对 |
| Open-Meteo 历史 API（同坐标） | 拉取同坐标同时段的历史再分析数据作实况 |
| 上传 CSV | 临时上传一份观测文件用于比对 |

参与验证的变量为气温、湿度、风速、降水；指标由独立模块计算：MAE（平均绝对误差）、RMSE（均方根误差）、Bias（平均误差，正负号表示系统性偏高或偏低）、相关系数 r。图表有三种：一一对应散点图、观测与预报的时序叠加图、误差分布直方图。配对要求观测与预报时间有重叠，且至少一个变量同时存在，否则会给出明确提示。

### 7.6 已知限制

- GFS 是免费公开模式，其分辨率与更新频次低于业务数值预报，本站不提供任何订正。
- 空气质量预报最长 7 天，与最长 16 天的 GFS 时效不齐。
- 极端值判断基于单点逐时序列，单点代表性有限，山区与沿海尤其明显。
- 生活指数中的紫外线由天气码推断，不是辐射观测值。

## 8. AI 读图解析

本章描述「[读图] AI 读图解析」Tab 的完整行为。该 Tab 取代原「智能分析与建议」标签，索引保持为 3，**不依赖已导入的数据**，零数据状态下可正常使用。

### 8.1 支持的图与不支持的图

适合上传的是带明确图面标注的气象图：地面与高空天气图、卫星云图、雷达回波图、模式形势图与要素预报图、探空图，以及带经纬网、色标、图例、等值线标注的各类分析图。

不适合上传的是：需要原始格点数据才能回答的问题（模型读图不重算物理量）、无任何标注的截图、被压缩到看不清等值线数值的小图、以及局部放大的畸变图。此外，含涉密或未公开信息的图片不应上传。

### 8.2 图片要求与四重上限

| 项目 | 上限 | 判定对象与行为 |
|---|---|---|
| 张数 | 最多 3 张 | 控制单次请求成本；多图用于对比不同时次或不同要素 |
| 原始字节硬上限 | 20 MB / 张 | **解码前**判定，超过即拒绝该图，提示「文件过大，请先自行压缩后上传」 |
| 单图体积 | 5 MB | 判定对象是**提交字节**。处理后仍超 5 MB 则该图标记失败并说明原因，不进入解读请求 |
| 合计体积 | 12 MB | 各图提交字节之和超限则整体拒绝，并提示精简张数 |
| 长边像素 | 上限 1600 px | 超过则等比缩放。气象图上的等值线数值与坐标标注需要保持可读，因此不采用更激进的压缩 |
| 长边像素 | 下限 200 px | 低于此值直接拒绝，提示分辨率过低、无解析价值 |
| 建议格式 | PNG / JPG / JPEG / WebP | 上传控件只接受这四种扩展名 |

处理全部在内存中完成，不写磁盘：先做原始字节闸门，再用图像库校验文件魔数（**不信任扩展名**），长边超限则等比缩放。**未触发缩放且原本就是 PNG 或 JPEG 的图会原样提交**，不做任何重编码，因此不存在「压缩后反而变大」或重编码带来的画质损失。需要重编码时（触发过缩放，或输入是 WebP、GIF），平台会同时试算 JPEG 质量 88 与 PNG，取体积更小的那一种：气象图多为线画类内容，此时通常 PNG 更小。重编码只做一次，不做二次降质重试，避免你无法判断画质损失来自处理还是原图。需要重编码的透明图会铺白底，避免透明区变黑掩盖浅色等值线。

伪装文件（扩展名合法但内容不是图片）会在魔数校验阶段被拒绝并说明；解码前设置了图像像素总量保护，可拦截解压炸弹类文件。

### 8.3 操作流程

1. 阅读上传区上方的隐私提示条：图片会发送至你所配置的 AI 服务商；含涉密或未公开信息的图片请勿上传。
2. 拖入或选择图片（最多 3 张，格式见上表）。
3. 查看图片清单：原尺寸、原体积、提交体积、是否需要重新编码，以及单张图是否因超限被拒及原因。
4. 可选填写补充说明（**限 500 字**），用于告诉模型图种与关注点，例如「这是 500 hPa 高空图，请重点关注槽脊位置」。补充说明会显著提高解读的针对性，建议填写。
5. 点击生成。生成前按钮区会显示本会话已生成次数（上限 10 次）、当前图片数与提交合计体积，以及粗略的图像 token 估算（按「宽 × 高 ÷ 750」估算并取整到百）。
6. 查看报告卡片与导出按钮。

**限频**：两次生成之间至少间隔 60 秒，每个会话最多生成 10 次。已生成的解读在会话内保留，可反复导出。

### 8.4 六段式解读结构

模型输出固定为六段，段落标题用方括号包裹，便于切片与展示：

1. **【图像信息】**：图片数量、文件名，以及图中可读出的图种与时间。
2. **【图面要素识别】**：坐标轴、色标、图例、单位、等值线间隔分别是什么。
3. **【主要分布特征】**：高 / 低压、槽脊、锋面、雨带、回波强度分布等可判读的系统。
4. **【关键数值与极值】**：图中可读的极值及其位置，必须与图面标注一致。
5. **【趋势与演变】**：仅当上传多图或图中含时序 / 多时次时输出；否则明确写「单图无法判断演变」。
6. **【风险提示与结论】**：面向业务与公众的可操作结论。

写入请求的系统指令中同时包含这些硬约束，逐条对模型明示：图中未标注的信息必须写「图中未标注」，不得推测；禁止编造站点名、地名、数值、时间、模式名称；引用数值时必须同时给出该数值在图中的位置特征（如「色标右端」「等值线密集区」）；无法确定图种时先说明不确定，再给出最可能的判读与其依据；气象结论仅供学习参考，最终以官方发布为准。

### 8.5 模型配置

读图解析需要单独配置一个具备图像输入能力的模型，与文本模型互不回落：

| 配置键 | 是否必需 | 缺省行为 |
|---|---|---|
| `LLM_VISION_MODEL` | **必需** | 未配置即视为「读图解析未配置」，页面给出含三个键名的配置指引，**不显示生成按钮**。**不会**回落到 `LLM_MODEL` |
| `LLM_VISION_API_KEY` | 选填 | 回落到 `LLM_API_KEY` |
| `LLM_VISION_BASE_URL` | 选填 | 回落到 `LLM_BASE_URL`，再回落到 `https://api.deepseek.com` |
| `LLM_VISION_MAX_TOKENS` | 选填 | 单次输出的 token 预算，省略即用默认 **16000**，合法范围 256–32000。推理型模型的思考过程也从这里扣额度，实测双图用掉 10437 个 reasoning tokens 而六段正文只需约 1100，预算给小了会表现为「返回空正文」+ 长度截断。预算是上限而非实际扣费，但推理型模型的实际用量可能上万 token，成本与耗时都明显高于非推理型模型 |

不回落文本模型是有意设计：默认文本模型没有视觉能力，若回落会造成「配置了却始终失败」的隐性故障，明确报「未配置」更可排查。请求采用 provider 无关的 OpenAI 兼容多模态协议，图片以 data URL 形式放在 user 消息的内容块中。

### 8.6 失败与降级行为

平台遵循「不假装降级」原则：视觉调用失败时**不生成任何替代文本**，因为文本模型读不了图，编造内容等同幻觉。

| 情况 | 行为 |
|---|---|
| `LLM_VISION_MODEL` 未配置 | 显示配置指引，不显示生成按钮 |
| 未上传图片 | 生成按钮为**禁用状态**（不发起调用，也无点击提示） |
| 单图处理后超 5 MB | 该图标记失败并说明原因，不进入请求；其余图片正常处理 |
| 单图原始字节超 20 MB | 拒绝该图，提示先行压缩 |
| 合计超 12 MB | 整体拒绝并提示精简张数 |
| 伪装文件（扩展名合法但非图片） | 魔数校验失败，拒绝并说明 |
| 长边 < 200 px | 拒绝并说明分辨率过低 |
| 调用超时、HTTP 错误、返回结构异常 | 显示可读原因（截断至 200 字），保留原图并提供重试按钮；不生成替代文本 |
| 返回正文为空 | 视为失败，并报出 `finish_reason`、模型名与原始响应片段，便于直接判因（见下） |

空正文的错误信息按「原因可判」设计，它会直接告诉你上游到底发生了什么，不需要你去猜：

| `finish_reason` | 含义与处置 |
|---|---|
| `stop` | 模型正常结束却没有正文，最常见的原因是该模型不支持图像输入，换一个真正的多模态模型 |
| `length` | 正文还没开始就撞上输出长度上限，缩短补充说明，或改用非推理型模型 |
| `content_filter` | 被服务商安全策略拦截，更换图片或模型 |
| 未提供 | 响应里没有该字段，多半是服务商的兼容层实现不完整，看响应片段判断 |

如果响应里只有 `reasoning_content` 而正文为空，错误信息会点明这一点，通常说明所配模型是推理型且未产出正文。
| `.docx` 导出失败 | 网页展示保留，单独提示导出失败 |

### 8.7 隐私与成本

- 图片会上传至你配置的 AI 服务商，平台本身不落盘；请勿上传涉密或未公开信息。
- API 密钥只从 Streamlit Secrets 读取，不写入代码、不下发前端、不写日志；异常信息截断后再展示。
- 成本控制由三重限制构成：最多 3 张图、单图 5 MB 与合计 12 MB 的体积上限、60 秒最小间隔与每会话 10 次上限，并在生成前把图片数、合计体积与 token 估算显示给你。

### 8.8 导出

解读完成后可导出两种文件：

| 格式 | 文件名 | 内容 |
|---|---|---|
| Word | `气象读图解析报告.docx` | 六段式解读正文，并嵌入本次上传的原始图片（宽度限制 15 cm），便于答辩与留档 |
| Markdown | `气象读图解析报告.md` | 模型原始输出文本 |

| METAR / SPECI | 报文类型标识 | 跳过 |
| 四位字母 | ICAO 机场代码 | 站号 |
| DDHHMMZ | 日期时间（世界时） | 时间戳（年份与月份取当前系统值） |
| dddssKT / dddssGggKT / VRBssKT / MPS | 风向风速与阵风 | 风向（°，VRB 视为不定）、风速（KT 换算为 m/s；有阵风时取阵风前的持续风） |
| 四位数字 | 能见度（米） | 能见度（km） |
| RA / SN / DZ / FG / BR / HZ / GR / TS 等 | 天气现象 | 映射为近似 WMO 天气码 |
| FEW / SCT / BKN / OVC / NSC / CAVOK / SKC / CLR | 云组 | 云量（成）：FEW 2、SCT 4、BKN 7、OVC 10，其余记 0 |
| TT/TdTd | 温度 / 露点 | 温度与露点（℃；M 前缀表示负值，`//` 或 `XX` 视为缺测） |
| QPPPP | 修正海平面气压 | 气压（hPa） |
| APPPP | 高度表拨正值（英寸汞柱） | 换算为 hPa |

### 10.3 已知限制

| 限制 | 说明与处置 |
|---|---|
| 日期缺年份与月份 | 报文中只有日与时，解析时使用当前系统年月；跨月核对时请手工改正时间 |
| 日期被截断到 28 日 | 日值超过 28 时按 28 处理，避免短月构造出非法日期 |
| SYNOP 的 4PPPP 组未解析 | 当前仅解析以 3 开头的本站气压组；出现 4PPPP 时气压字段留空 |
| METAR 云底高度未解析 | 只取云量等级，高度数值不写入 |
| 能见度识别偏保守 | METAR 中任何四位纯数字组都会被尝试当作能见度，遇到跑道视程等多组数字时需要人工核对结果 |
| 天气码为近似映射 | METAR 天气现象码被压成少量 WMO 码，粒度低于原文 |
| 定组未覆盖 | 不支持补充天气组、风切变、趋势预报等扩展组，也不支持 BUFR / GRIB 报文 |

## 11. ERA5 再分析数据获取

ERA5 数据由 Copernicus Climate Data Store（CDS）提供。平台的设计是「你不必把 CDS 凭证交给网站」：参数在网页上选好，平台生成一个可离线运行的脚本包，你在自己电脑上打开终端运行它，脚本下载并转换出 CSV，再把 CSV 拖回平台继续分析。应用侧不安装也不导入 cdsapi / xarray / netCDF4，因此部署环境不会因为它们缺失而失败。

### 11.1 第一次使用：注册与许可

1. 访问 CDS 网站注册免费账号并登录。
2. **在目标数据集的下载页手工接受数据集许可**（页面底部的 Terms of use 区块）。这一步无法用 API 代办，是下载失败最常见的原因：许可未接受时请求会在提交阶段被拒绝，报错原文为 `Client has not agreed to the required terms and conditions`。已接受的许可清单可在个人资料页底部查看。
3. 在个人资料页生成 API Key。
4. 在本机安装客户端：`pip install "cdsapi>=0.7.7"`。低于 0.7.7 的版本在部分认证与下载路径上表现不同，建议直接使用该版本或更高。
5. 创建凭证文件 `~/.cdsapirc`，内容只有两行：

   ```
   url: https://cds.climate.copernicus.eu/api
   key: 你的API-Key
   ```

   **没有 UID 字段。** 旧式 `uid:key` 写法会让客户端走到已废弃的 LegacyClient 分支而失败；地址也不要再用 `/api/v2` 或 `cds-beta`，两者均已停用。
6. 文件放置位置：Windows 为 `C:\Users\<你的用户名>\.cdsapirc`，macOS 为 `/Users/<你的用户名>/.cdsapirc`，Linux 为 `/home/<你的用户名>/.cdsapirc`。脚本包内的 `.cdsapirc.example` 可直接复制参考。

### 11.2 第二步：在平台上选择参数

进入数据导入 Tab 的「[网络] API 数据获取」→「ERA5 (CDS 引导)」子标签。页面顶部有一个「[说明] 如何获取 ERA5 数据」折叠区，内容与本节一致。

**四种产品**：

| 产品 | 数据集 | 分辨率 | 时间范围与时效 | product_type | 字段数上限 |
|---|---|---|---|---|---|
| ERA5-Land (地表小时, 0.1°) | reanalysis-era5-land | 0.1° × 0.1° | 1950 年至今（约滞后 2–3 个月） | 不接受该键 | 12 000 |
| ERA5 再分析单层 (0.25°) | reanalysis-era5-single-levels | 0.25° × 0.25° | 1940 年至今 | reanalysis | 120 000 |
| ERA5 气压层 (0.25°) | reanalysis-era5-pressure-levels | 0.25° × 0.25° | 1940 年至今 | reanalysis | 120 000 |
| ERA5-Land 月均值 (0.1°) | reanalysis-era5-land-monthly-means | 0.1° × 0.1° | 1950 年至今 | monthly_averaged_reanalysis | 100 000 |

产品说明卡会同时显示分辨率、字段数上限、时间范围与 product_type，并提供「[打开] 该数据集 CDS 页面」按钮直达下载页（第一步接受许可也在该页完成）。

**变量按分组展示**，共 8 组：温度、湿度、风、气压、降水与蒸发、云与辐射、陆面、大气层结。每组是一个多选控件，显示格式统一为「中文名（API 变量名，单位，换算说明）」，例如「2m 气温（2m_temperature，K，K → ℃（减 273.15））」。首次进入某个产品时，每组默认勾选该组第一个变量，避免出现空选择。同一变量在多个组中出现时按组内归属展示，选择结果去重。

**常用组合预设**共 5 个，选中后自动切换产品并勾选对应变量，仍可手动增减：

| 预设 | 产品 | 包含变量 |
|---|---|---|
| 站点气象常用（ERA5-Land） | ERA5-Land (地表小时, 0.1°) | 2m 气温、2m 露点温度、地面气压、10m 纬向风 u、10m 经向风 v |
| 降水与蒸发（ERA5-Land） | ERA5-Land (地表小时, 0.1°) | 总降水、潜在蒸发 |
| 土壤与陆面（ERA5-Land） | ERA5-Land (地表小时, 0.1°) | 土壤温度（0–7cm）、土壤体积含水量（0–7cm）、雪深 |
| 高空环流（气压层） | ERA5 气压层 (0.25°) | 位势、温度、纬向风 u、经向风 v、比湿 |
| 云与辐射（单层） | ERA5 再分析单层 (0.25°) | 总云量、下行短波辐射、边界层高度 |

**不提供的变量会显示但不可选**，并给出原因与「切换到该产品」按钮：ERA5-Land 小时与月均值不提供相对湿度与总云量；单层产品不提供相对湿度；气压层不提供位势高度（应改选位势，再按位势高度 = 位势 ÷ 9.80665 换算）。把不支持项隐藏会让人误以为该变量在 CDS 中根本不存在，因此这里选择显式展示。

**气压层产品**还需选择气压层，共 37 个有效层次：1、2、3、5、7、10、20、30、50、70、100、125、150、175、200、225、250、300、350、400、450、500、550、600、650、700、750、775、800、825、850、875、900、925、950、975、1000 hPa，默认勾选 500 与 850。

**年份上限**为「当前年减一」，因为 ERA5 约滞后 2–3 个月，当年数据不完整。月均值产品不接受「日」键，时间只取 00:00。

**请求规模预警**在生成脚本包之前进行。字段数估算公式为「变量数 × 年数 × 各月天数之和 × 时次数 × 气压层数」（月均值产品按「变量数 × 年数 × 月数」计，2 月按 29 天安全高估），与所选产品的上限比较：

| 产品 | 上限 | 超限时的表现 |
|---|---|---|
| ERA5-Land 小时 | 12 000 | 显示错误并**禁止生成脚本包**，同时提示缩小区域、减少变量或缩短时段 |
| ERA5-Land 月均值 | 100 000 | 同上 |
| ERA5 单层 | 120 000 | 同上 |
| ERA5 气压层 | 120 000 | 同上 |

未超限时以说明文字给出「请求规模约 N 个字段（上限 M）」。CDS 侧对超限请求不会立即报错，而是转入长时间排队，因此这一预警把反馈提前到了点击之前。

页面底部还提供「在 CDS 官网手动填表（不使用脚本包时）」折叠区，把本次选择渲染成与官网表单字段一致的可复制文本，便于不用脚本的用户逐项照抄。

### 11.3 第三步：下载脚本包

参数校验通过且未超限时，可通过「[下载] ERA5 下载脚本包 (.zip)」取得 `era5_download_pack.zip`，内含六个文件：

| 文件 | 作用 |
|---|---|
| `era5_download.py` | 主脚本，请求参数已烘焙在文件顶部的 PARAMS 中，无需手工编辑 |
| `.cdsapirc.example` | 凭证文件示例，含放置位置说明与「没有 uid 字段」的提醒 |
| `README.txt` | 主路径说明：如何打开终端、三条命令、许可接受链接、常见错误对照表 |
| `requirements.txt` | `cdsapi>=0.7.7`、`xarray`、`netCDF4`、`pandas`，只在你的本机安装 |
| `一键运行.bat` | Windows 可选加速器，**非主路径** |
| `运行.sh` | macOS / Linux 可选加速器，**非主路径**，带 `set -e` |

### 11.4 第四步：手动打开终端运行

主路径是手动打开终端敲三条命令，不依赖任何双击脚本。

1. 解压 ZIP 到一个你有写权限的目录。
2. 打开终端：
   - Windows：按 `Win + R` 输入 `cmd` 回车；或点开始菜单搜索 PowerShell 并打开。
   - macOS：打开「访达 → 应用程序 → 实用工具 → 终端」。
   - Linux：在桌面或文件管理器中打开终端。
3. 在终端里依次执行三条命令，把第一行换成你解压后的目录：

   ```
   cd 解压后的目录路径
   python -m pip install -r requirements.txt
   python era5_download.py
   ```

`一键运行.bat` 与 `运行.sh` 只是把后两条命令合并执行，属于可选加速器：命令行不熟时双击即可，不安装、不使用它们也完全可以。

### 11.5 脚本会做什么

1. 读取本机 `~/.cdsapirc`，**不接受任何命令行密钥参数**，也不把密钥写进任何输出。找不到配置文件时打印创建方法并以退出码 2 结束。
2. 按烘焙好的参数向 CDS 提交请求。状态从 queued 变为 running 可能需要数十分钟到数小时；终端可以关闭，请求 ID 会打印出来，之后可凭它在 CDS 网页取回结果。脚本以 `progress=True` 显示进度。
3. 下载结果为 ZIP 时（多变量或多文件请求仍可能返回 ZIP）自动解包出全部 `.nc` 到 `era5_nc/` 目录，解包时拒绝绝对路径与 `..` 路径穿越。
4. 把 netCDF 转为宽表 CSV，并完成单位换算：气温与露点 K → ℃、累计降水 m → mm、气压 Pa → hPa、云量 0–1 → 0–100 %、位势 → 位势高度（÷ 9.80665），u/v 分量合成为风速 `sqrt(u²+v²)` 与气象风向 `(270 − degrees(atan2(v, u))) % 360`。
5. 兼容时间维名为 `time` 或 `valid_time`；存在 `expver` 维（ERA5T 与最终产品并存）时自动合并；区域请求的多个格点做区域平均，需要单点原值请把区域缩到单个格点。
6. 输出宽表 CSV：`era5_export.csv`，时间列统一为 ISO 8601 字符串，编码为 UTF-8 带 BOM。

CSV 列名映射（脚本内固定）：

| ERA5 变量 | CSV 列名 | 换算 |
|---|---|---|
| 2m_temperature | temperature | K → ℃ |
| 2m_dewpoint_temperature | dewpoint | K → ℃ |
| skin_temperature | skin_temperature | K → ℃ |
| surface_pressure | pressure | Pa → hPa |
| mean_sea_level_pressure | mslp | Pa → hPa |
| total_precipitation | precipitation | m → mm |
| 10m_u_component_of_wind + 10m_v_component_of_wind | wind_speed、wind_direction | 由分量合成 |
| total_cloud_cover / cloud_cover | cloud_cover | 0–1 → % |
| relative_humidity | humidity | 不换算 |
| snow_depth | snow_depth | 不换算 |
| geopotential | geopotential_height | ÷ 9.80665 |
| 其他变量 | 保留原变量名 | 不换算 |

### 11.6 第五步：把 CSV 回导平台

回到数据导入 Tab，用「📁 上传文件」选择 `era5_export.csv`。CSV 的时间列为 `timestamp`，气象要素列名与平台标准字段一致，因此能被直接识别并进入质控与可视化流程。若列名未被识别，请对照第 5.3 节的标准字段表核对。

### 11.7 常见错误对照

| 错误信息 | 原因 | 处置 |
|---|---|---|
| `Client has not agreed to the required terms and conditions` | 该数据集的许可尚未由你的账号手工接受 | 登录 CDS，打开该数据集下载页，在页面底部勾选并接受许可后重新运行脚本；可在个人资料页核对已接受许可清单 |
| HTTP 422（请求参数不被该数据集接受） | 变量名或请求键不被该数据集接受 | 脚本会打印本次提交的键集；登录 CDS 表单逐项核对。注意 `format` 已废弃，必须用 `data_format`（grib / netcdf）与 `download_format`（zip / unarchived）；缺省 `data_format` 会静默返回 GRIB 而不是 netCDF |
| HTTP 403，`cost limits exceeded` | 触发了 netCDF 成本限额（2025 年 4 月起） | 缩小请求范围：减少变量、缩短时段或缩小区域后重试 |
| `Number of API queued requests for this dataset is temporarily limited` | 该数据集同时排队的请求数达到上限 | 等待已有请求完成，或减小请求规模后稍后重试 |
| 下载得到 ZIP 文件 | 多变量或多文件请求的正常返回 | 无需处理，脚本会自动解包出全部 `.nc` |
| 时间维名是 `valid_time` 而不是 `time` | 新版 netCDF 的正常命名 | 无需处理，脚本两种都兼容 |
| 未找到配置文件 `~/.cdsapirc` | 凭证文件缺失或位置不对 | 按第 11.1 节第 5、6 步创建，注意没有 UID 字段 |
| 脚本报缺少 xarray / netCDF4 | 本机未安装依赖 | 在终端执行 `python -m pip install -r requirements.txt` |
| 请求排队数小时未完成 | 请求规模大或 CDS 队列繁忙 | 关闭终端不影响处理，凭请求 ID 到 CDS 网页取回；或缩小请求分批下载 |
| 回导后时间列解析异常 | 上游返回的 ERA5T 数据被后续修订，或命中了不完整缓存 | 重新下载同一时段，或改选较早期次 |

### 12.3 自定义检测阈值（七类）

在「[设置] 自定义检测阈值」标题下展开「[工具] 调整阈值（覆盖国家标准）」。默认值即国家标准值，修改后需点底部的「[OK] 应用自定义阈值」按钮生效。

| 类别 | 输入项 | 默认值 | 对应标准口径 |
|---|---|---|---|
| 高温 | 黄色 ≥ / 橙色 ≥ / 红色 ≥ | 35.0 / 37.0 / 40.0 ℃ | 黄色为连续 3 天日最高气温达标；橙、红为 24 小时内最高气温达标 |
| 大风 | 蓝色 ≥ / 黄色 ≥ / 橙色 ≥ / 红色 ≥ | 10.8 / 17.2 / 24.5 / 32.7 m/s | 对应平均风力 6 / 8 / 10 / 12 级 |
| 大雾 | 黄色 < / 橙色 < / 红色 < | 500 / 200 / 50 m | 能见度阈值 |
| 暴雨 | 蓝色 ≥（12h）/ 黄色 ≥（6h）/ 橙色 ≥（3h）/ 红色 ≥（3h） | 50 / 50 / 50 / 100 mm | 按降水历时区分等级 |
| 霜冻 | 蓝色 ≤ / 黄色 ≤ / 橙色 ≤ | 0 / −3 / −5 ℃ | 地面最低温度阈值 |
| 霾 | 黄色 < / 橙色 < | 3000 / 2000 m | 能见度阈值 |
| 雷电 | 最近 N 小时内的雷暴码 | 6（可设 1–24） | 时间窗口，非数值阈值 |

**寒潮阈值不在侧边栏调整范围内**，它使用标准值：蓝色为 48 小时降温 ≥ 8 ℃ 且最低气温 ≤ 4 ℃；黄色为 24 小时降温 ≥ 10 ℃ 且最低气温 ≤ 4 ℃；橙色为 24 小时降温 ≥ 12 ℃ 且最低气温 ≤ 0 ℃；红色为 24 小时降温 ≥ 16 ℃ 且最低气温 ≤ 0 ℃。

关于作用域：界面上的说明写的是「仅影响当前会话」，实现上阈值存放在分析模块的进程级全局变量中，因此它会一直生效到你再次点击「应用自定义阈值」覆盖，且同一服务进程内的其他会话也会看到同一套阈值。多人共用部署时，修改阈值前请知悉这一点。

| 「[显示] 天气墙」 | 开启 | 显示或隐藏首页天气墙，选择同样持久化 |

### 12.5 导入历史、重置与页脚

**导入历史**最多显示最近 3 条记录，格式为「时间 | 来源 | 记录数」，会话内最多保留 5 条。

**「[刷新] 重置当前模块数据」**只清理当前 Tab 的业务数据，保留登录态、导航栈与阈值设置，并按 Tab 精确清理：

| Tab | 清理的会话键 |

## 13. 常见问题（FAQ）

### 13.1 安装启动

**Q1 打开页面只看到登录页，看不到任何功能。**
这是预期的登录门禁。若登录页同时提示「未配置 Supabase 密钥」，说明 `.streamlit/secrets.toml` 缺失或键为空：按第 3.3 节补齐 `SUPABASE_URL` 与 `SUPABASE_ANON_KEY` 后重启应用。若已配置仍无法登录，检查 Supabase 项目是否已完成创建、邮箱确认开关是否按第 3.3 节设置。

**Q2 终端报端口被占用，浏览器打不开。**
查看终端实际打印的地址；端口来自 `.streamlit/config.toml` 的 `port`。可修改该值或在启动命令后追加端口参数，然后重新访问打印出的地址。

**Q3 提示「DNS 解析失败」。**
按顺序核对：URL 是否完整且无多余空格；是否误带了 `/rest/v1/` 路径；Supabase 项目是否已创建；刚创建的项目 DNS 生效可能需 3–5 分钟。

**Q4 界面图表全部提示渲染失败。**
先在侧边栏开启「[调试] 显示详细错误信息」，展开堆栈定位到具体区块名。若与你改动的配色或图表模板有关，可用仓库自带的审计脚本排查：CSS 变量引用完整性、图表是否误用了只有浏览器才识别的 `var()`、图表颜色是否为绘图库认可的实值。

### 13.2 数据导入

**Q5 上传后提示「未检测到时间列」。**
按第 5.4 节整理：优先把时间列改名为 `timestamp` 或「时间」；或使用 `year / month / day / hour` 四列；或在列选择器中手工指定。完全无时间信息时平台会用序号生成时间轴，此时时间筛选与逐时质控的意义有限。

**Q6 导入成功但图表大多是空白。**
多半是列名未识别。展开「[搜索] 字段识别详情」查看「未识别字段」列表，按第 5.3 节的标准字段表改名后重新导入。综合看板需要气温、气压、湿度、风速四个字段，缺失项会在页面上直接列出。

**Q7 质量评分很低，但数据看起来没问题。**
逐条看质控问题列表。最常见的原因是单位口径不一致：气压写成 Pa、降水写成 m、云量写成 0–1 比例，都会触发大量「范围异常」。另一种是数据本身不是逐时序列，却被要求按逐时规则比较突跳。

**Q8 中文列名乱码。**
CSV 编码不是 UTF-8。平台会依次尝试 UTF-8、GBK、GB2312、GB18030 与 latin-1，仍乱码时请用 Excel / WPS 另存为 UTF-8 编码的 CSV 后重新上传。

**Q9 上传的 Excel 报「内容过大」。**
xlsx 解压后的总体积超过 200 MB（防压缩炸弹保护）。另存为 CSV 后导入通常即可通过。

### 13.3 AQI 与标准

**Q10 页面上的 AQI 用的是哪一版标准？**
分指数口径为 HJ 633-2012，由配置中的标准标注常量统一渲染在页面与图表说明上。详见第 14 章的说明。

**Q11 为什么同一个 PM2.5 浓度在别处算出的 AQI 不同？**
AQI 依赖分指数表、评价时段与污染物组合。本平台的 PM2.5 分指数按 24 小时均值表定义，预报侧以逐时浓度近似代入，与严格按日均值计算的结果会有差异；综合 AQI 取各污染物分指数的最大值，参与项越多，综合值越高。

**Q12 空气质量面板的虚线代表什么？**
代表浓度限值参照线，不是 AQI 阈值。四条线分别为 PM2.5 50、PM10 100、SO₂ 100、NOx 60 μg/m³，属二级标准日均限值口径，来自配置中的浓度限值表。

**Q13 浓度极高时 AQI 会不会反而显示为优？**
不会。分指数超出末档时按末档斜率线性外推，并钳制到该污染物自身的最大分指数节点（颗粒物与 CO 为 500，气态污染物为 200），不会回落到 0。

### 13.4 读图解析

**Q14 页面提示读图解析未配置。**
需要单独配置具备图像输入能力的模型键 `LLM_VISION_MODEL`（可选配 `LLM_VISION_API_KEY` 与 `LLM_VISION_BASE_URL`）。它**不会**回落到文本模型，这是有意设计，避免出现「配置了却始终失败」。详见第 8.5 节。

**Q15 上传图片后提示文件过大。**
三个上限分别判定：原始字节超过 20 MB 直接拒绝；处理后单图超过 5 MB 拒绝该图；各图提交字节合计超过 12 MB 整体拒绝。处置：用图像工具把长边压到 1600 px 以内再上传，或减少张数。不必刻意转成 JPEG——平台对 PNG 与 JPEG 都会自动取更小者，对不需要缩放的 PNG/JPEG 更是原样提交。

**Q16 上传成功但解读质量差。**
在补充说明里写清图种与关注点（限 500 字），例如「这是 500 hPa 高空图，请重点关注槽脊位置」。另外确认图面标注可读：等值线数值、色标与坐标被压缩到看不清时，模型只能写「图中未标注」。

**Q17 解读失败，能不能退回文本模型出个摘要？**
不能，这是刻意的：文本模型无法读图，生成的替代文本等同编造。失败时界面会保留原图、给出可读原因并提供重试按钮。

**Q17b 提示「视觉模型返回空正文」。**
这条错误会同时给出 `finish_reason`、模型名与原始响应片段。最常见两种：`finish_reason=stop` 说明该模型不支持图像输入，`finish_reason=length` 说明输出长度被推理内容吃掉了。按第 8.6 节的对照表处置，或把响应片段留作排查依据。

**Q18 生成的次数受限提示。**
会话级限频为两次生成至少间隔 60 秒、每会话最多 10 次。等待计时结束或新开会话即可。

### 13.5 ERA5

**Q19 脚本报许可未接受。**
这是最高频的失败原因。登录 CDS，打开该数据集下载页，在页面底部手工勾选并接受许可，然后重新运行脚本。API 无法代为接受。

**Q20 报 HTTP 422。**
请求参数不被该数据集接受。脚本会打印本次提交的键集，请登录 CDS 表单核对。重点检查：`format` 是否已被 `data_format` 与 `download_format` 取代；所选变量是否属于该数据集（例如相对湿度只在气压层产品提供）。

**Q21 请求一直排队。**
字段数超限不会报错而是长期排队。回平台查看请求规模估算，按提示缩小区域、减少变量或缩短时段，分批下载。终端可以关闭，凭请求 ID 稍后取回结果。

**Q22 报 HTTP 403 成本限额。**
netCDF 请求有成本限额，超限直接返回 403。同样按「缩小区域 / 减少变量 / 缩短时段」处置；如只是偶尔一次，也可稍后重试。

**Q23 下载得到的是 ZIP 而不是 nc。**
正常现象，多变量或多文件请求会返回 ZIP，脚本会自动解包到 `era5_nc/` 并继续转换。

**Q24 回导的 CSV 时间列不认。**
脚本输出的时间列固定名为 `timestamp`，格式为 ISO 8601。若仍识别异常，请确认上传的确实是 `era5_export.csv` 而不是 `era5_download.nc`。

### 13.6 报告导出

**Q25 报告里没有图片。**
这是设计取舍：报告为表格化排版，便于检索与打印；交互式图表请在界面查看，并逐图点「📥 导出 HTML」。

**Q26 报告缺少预报章节或预警章节。**
章节按数据可用性自动取舍。缺少预报章节说明本会话未获取 GFS 预报；缺少预警章节说明未检出触发阈值的天气事件，属正常结果。

**Q27 封面上的质量评分是 0/100。**
说明本会话未运行过数据质量控制。回到数据导入向导第 2 步（或跳走向导路径下方）查看一次质控报告，评分即会写入并被报告读取。

**Q28 CSV 里以等号或加号开头的单元格被加了单引号。**
这是公式注入防护，避免在 Excel / WPS 中被当作公式执行。单引号在表格中不显示，单元格内容不变。

| NOx | 30 | 60 | 150 |
| PM10 | 50 | 100 | — |

### 14.2 AQI 分指数断点表（HJ 633-2012）

| 污染物 | 评价时段 | 浓度节点 | IAQI 上限 |
|---|---|---|---|
| PM2.5 | 24 小时 | 0、35、75、115、150、250、350、500 μg/m³ | 500 |
| PM10 | 24 小时 | 0、50、150、250、350、420、500、600 μg/m³ | 500 |
| SO₂ | 1 小时 | 0、150、500、650、800 μg/m³ | 200 |
| NO₂ | 1 小时 | 0、100、200、700、1200 μg/m³ | 200 |
| CO | 1 小时 | 0、5、10、35、60、90、120、150 mg/m³ | 500 |
| O₃ | 1 小时 | 0、160、200、300、400 μg/m³ | 200 |

计算规则：分指数按区间线性内插，超出末档时按末档斜率外推后钳制到该污染物自身的最大分指数节点；落在无效区间或非有限值时不参与计算；综合 AQI 取各分指数的最大值，AQI ≤ 50 时首要污染物为空，并列最大时全部列出。等级区间见第 7.2 节的六级表。

已知局限：气态污染物的 1 小时均值表用于逐时浓度是正确的；若把时段均值代入同一张表，会高估气态污染物的分指数。评价时段口径的重新定义不在当前版本范围内。
